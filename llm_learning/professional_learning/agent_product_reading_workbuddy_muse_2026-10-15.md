# WorkBuddy / Meta Muse：产品阅读、开源替代与架构学习计划

> 核对日期：2026-10-15。产品说明、开源项目与作者分析分开记录。
> 本次未登录产品、未接邮箱 / 支付、未运行性能测试；所有产品能力均注明依据，不推测闭源内部代码。

## 1. 身份已确认，先纠正此前的不确定项

- **WorkBuddy**：腾讯 Cloud CodeBuddy 团队的办公 Agent 工作台。[官方机器可读产品介绍](https://www.workbuddy.ai/llms.txt)明确区分办公 Work Mode 与 Coding Mode，以及 WorkBuddy 和 CodeBuddy。
- **Muse**：用户提供的 [Meta Muse 官网](https://ai.meta.com/muse/)。本次使用本地代理成功取得页面元信息，标题与描述明确为 Meta personal AI agent；正文依赖动态页面，不能只凭元信息总结完整能力。
- 进一步读取到 [Meta 官方发布文](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)，发表于 **2026-09-08**，页面修改日期 **2026-09-30**。这是本文 Muse 能力摘要的主要依据。
- Muse 产品、Muse Spark 模型和 Manus 是不同对象。Muse 发布文说明由 Muse Spark 支持，但“发布模型”不等于“开源完整 Agent Harness”。
- 本次没有确认 WorkBuddy / Muse 完整核心 Harness 的官方开源仓库；这不是对它们所有组件、未来计划或依赖代码的“全部闭源”判断。

## 2. 与 Coding Agent 不同，办公 / 个人 Agent 值得研究什么？

| 维度 | WorkBuddy 官方说明 | Muse 官方发布文 | 工作应用 / 架构思考（本文分析） |
|---|---|---|---|
| 主要目标 | 文件、表格、报告、演示与分析等可验收产物 | 个人目标、邮件、日程、浏览与购买等跨服务任务 | 任务结果不只是文本；产物和外部状态要有验证方式 |
| 执行位置 | 授权本地文件、任务 workspace；也有远程入口与连接器 | 专用云端 Muse Secure VM，应用关闭后可继续任务 | 云上 / 本地各自涉及凭据、权限、恢复与生命周期，不能仅凭部署位置判断隐私 |
| 交互入口 | 桌面工作台，支持多类消息渠道远程分派 | Muse 应用 / 网页与 WhatsApp 等 | 一项任务跨入口续接，需身份与状态关联 |
| 记忆 | 偏好与相关会话上下文 | 记住偏好、目标与细节，支持要求遗忘 | 必须研究写入来源、纠错、用户可见性与删除，不只看“记忆”开关 |
| 主动行为 | 定时 / 自动化任务、多任务 | 主动建议、推进长期目标 | 触发器、授权范围、通知和取消应可管理，不能无限后台执行 |
| 高风险动作 | Default Permissions / Full Access、sandbox 与确认 | 官方描述 Sentinel 介入出网，敏感动作确认、凭据隔离与审计 | 将决策与可执行权限分开；确认绑定参数，不能把安全宣传当已验证保证 |

这不是同预算的横向测评，也不支持“国内只能办公、国外只能个人”等结论。二者场景有交集，具体功能随地区、版本、套餐和连接器变化。

## 3. 找到的开源学习替代：按能力对应，不冒充原产品源码

### 3.1 Rowboat：优先研究办公上下文与工作台

- [官方仓库](https://github.com/rowboatlabs/rowboat)；Apache-2.0。
- 本轮固定 commit：`eb3122953a4bdb96ba43914bc12ed763202ea976`；最近提交 2026-10-15 06:01 UTC。
- README 定位为带文档、白板、邮件等能力的开源个人助手；描述对邮件、会议、Slack、会话等工作资料组织知识图谱，并提供后台 Agent 与工作区。
- 提供 Windows / macOS / Linux 下载入口，但本次未验证安装或各平台功能是否一致。

**与 WorkBuddy 对应的学习价值：**

1. 从资料与消息接入，到可检索 / 可更新的工作上下文。
2. 知识图谱、文档与聊天状态如何区分，而非“所有东西都塞进 prompt”。
3. 邮件草稿、文档、图表等产物怎样进入用户审核流程。
4. 定时 / 事件触发任务如何管理状态、失败与通知。

**已确认的入口：** [固定版本 README](https://github.com/rowboatlabs/rowboat/blob/eb3122953a4bdb96ba43914bc12ed763202ea976/README.md)、[apps](https://github.com/rowboatlabs/rowboat/tree/eb3122953a4bdb96ba43914bc12ed763202ea976/apps)（包含 x、harbor）。具体消息 → Agent → 连接器 → 产物的调用关系需后续源码追踪，不能仅凭目录名断言。

**边界：** 这不是 WorkBuddy 的开源复刻，不能保证相同 Office 文件保真度、企业权限、多 Agent 或数据本地性。使用 Claude Code / Codex 等外部能力时，还要区分本项目自己实现和委托的部分。

### 3.2 OpenClaw：优先研究持续运行的个人助手

- [官方仓库](https://github.com/openclaw/openclaw)；MIT。
- 本轮固定 commit：`cd3eb90f875295e90c6fb7e0c10fc72920b5235a`；最近提交 2026-10-15 08:19 UTC。
- README 描述本机运行的助手、多消息渠道、Gateway、sessions、工具 / skills、设备节点与定时功能。
- [官方 Gateway 架构](https://docs.openclaw.ai/concepts/architecture)说明客户端、节点、协议、配对和事件流。

**与 Muse 对应的学习价值：**

1. 不同聊天入口如何经过统一控制平面关联会话与身份。
2. 主动定时任务与普通用户请求如何共享执行系统。
3. 本地设备能力、连接器、配对与授权如何分层。
4. 长程任务的事件反馈、状态更新、重复提交与取消。

**入口：** [固定版本 README](https://github.com/openclaw/openclaw/blob/cd3eb90f875295e90c6fb7e0c10fc72920b5235a/README.md)、[src](https://github.com/openclaw/openclaw/tree/cd3eb90f875295e90c6fb7e0c10fc72920b5235a/src)中 agents、channels、context-engine、cron 等；按真实引用继续追 Gateway 与会话实现。

**边界：** 这不是 Meta Muse 的已证实开源版本，也不证明具备 Muse 宣称的 Secure VM / Sentinel / 凭据隔离。README 明确提醒主会话工具可能在宿主执行，sandbox 需配置。状态在本机不等于 prompt 不发给外部模型 / 消息平台。

### 3.3 怎么加入，而不变成五个巨型仓库全部精读？

保留 [原 Harness 路线](index-2026-10-08.md)，增加两条产品视角：

- **运行时主线**：Deep Agents → DeepSeek Harness；OpenCode 作为 coding 对照。
- **产品主线**：Rowboat 对照办公工作台；OpenClaw 对照个人 / 多渠道助手。

五个是候选阅读池，**不要求五个同深度部署**。A＋B 后先看两种产品架构各一次，再从运行时、办公、个人方向中选 **2 个精读 + 1 个对照**；最多维护一套自己的完整项目。选办公 / 个人项目精读时，替换原计划中的一个名额，不无限叠加。

## 4. 精选阅读：先读什么，能得到什么证据？

### W1. WorkBuddy 官方产品介绍：建立能力地图

- [机器可读官方介绍](https://www.workbuddy.ai/llms.txt)；持续更新页面，首次发布日期未明确，2026-10-15 核对。
- **性质：** 厂商产品说明，不是独立评测。
- **摘要：** 以可验收文件产物为中心；任务 workspace、并行任务、skills / MCP、连接器、记忆与远程消息入口共同构成办公系统。
- **阅读重点：** 区分“入口”“执行环境”“扩展能力”“状态”“产物”；不要只记多 Agent 数量。
- **不能证明：** 任务成功率、节省时间、失败率、隐私实现或内部采用哪种规划算法。

### W2. WorkBuddy Permission Modes：最值得结合阶段 A 阅读

- [官方权限模式文档](https://www.workbuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Permission-Modes)；持续更新页，2026-10-15 在浏览器读取正文。
- **性质：** 产品行为与操作说明，不是安全审计。
- **摘要：** workspace 定义任务范围；Default Permissions 对敏感路径、删除、脚本 / 命令及网络等风险触发确认；文档说明 sandbox、删除保护与 Windows 文件备份。Full Access 关闭相应确认流，不意味着更安全。
- **学习问题：** “运行前检查脚本文本”与“执行边界控制”有何不同？取消确认是否真未执行？批准后参数改变会怎样？
- **本文分析：** 工作台必须把用户意图转换成可执行范围；只在 system prompt 写“不要修改重要文件”不足够。
- **限制：** 不把说明直接当作所有平台上限制均可靠执行的实测证据，sandbox 的强度需单独验证。

### W3. WorkBuddy 数据分析案例：可用来设计验收，不当作效果证明

- [Data Analysis and Visualization for Excel and CSV Files](https://www.workbuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Data-Analysis)；2026-10-15 在浏览器读取正文，首次发表日期未明确。
- **性质：** 厂商短案例，内容主要是输入方式与示例提示。
- **摘要：** 指定 CSV / Excel，提出地区比较、趋势或图表需求，获得分析与可用产物。
- **本文分析：** 真正评测应核对表头、单位、缺失值、跨表关联、聚合数值与产物能否打开；“图很漂亮”不等于数字正确。预测未来收入还需独立预测验证。
- **限制：** 页面没有提供可复现完整数据、失败案例或统计成功率，不能称为严谨 benchmark。

### W4. WorkBuddy Bench：把办公“交付物”变成执行评测

- [Tencent/workbuddy-bench](https://github.com/Tencent/workbuddy-bench)；2026-10-15 核对 README。
- **性质：** 腾讯发布的评测框架，不是独立第三方评测，也不是产品 Harness。
- **摘要：** 在 Docker 工作区让外部 Agent 产出 patch、文件或报告，捕获轨迹、测试与效率并评分；基于 Harbor。README 列 Code 80、Web 70、Office 50、Security 60 个任务。
- **重点读 Office：** 多格式文件的结构、关系、状态与证据链，比单纯增大表格行数更能考验实际办公能力。
- **限制：** 本次未跑 benchmark、未审核全部任务或许可证；公开任务有污染风险，发布者定义的任务范围也不等于所有办公场景。

- **日期：** 发布 2026-09-08，修改 2026-09-30；2026-10-15 核对。

## 5. 从文章中提炼的应用思考（本文总结，不是实测结论）

1. **办公 Agent 的单位应是“交付物”**：表格数字、报告依据、文件完整性、编辑历史与可复核结果，而不是一次漂亮聊天。
2. **个人 Agent 的单位应是“持续目标”**：会话只是入口，任务可能跨天、跨应用、跨设备；需要明确何时自主推进、何时询问、何时过期。
3. **记忆是产品契约，不只是向量库**：用户能否知道记住了什么、改正错记、撤销连接和删除信息，比“使用了哪种 Memory 类型”更关键。
4. **代用户行动需要边界**：草拟与发送、筛选与下单、分析与修改文件分别授权；审批对象、参数和时效需要绑定。
5. **本地与云端各有权衡**：本地文件可能发给模型服务；云 VM 也需核实访问、加密和运营权限。不能把部署位置直接等同于安全。
6. **主动性需要单独评测**：不只看任务成功，还看误触发、打扰、重复执行、取消后行动和通知负担。
7. **连接器越多，评测不应只加数量**：需测试身份、权限、失效与故障传播。自然语言入口可以简洁，但背后的状态与执行不能模糊。

## 6. A＋B 后的具体阅读任务

### 办公线：Rowboat 对照 WorkBuddy 的产品需求

使用虚构 / 去标识化文件：

```text
两张 CSV / Excel + 一份说明
 → 找字段与单位
 → 汇总并核对
 → 产出报告 / 表格
 → 用户审阅
```

读源码时追：文件 / 连接器接入 → 上下文或知识组织 → Agent 调用 → 产物 → 审核。注入缺字段、矛盾说明、工具失败与覆盖同名文件风险。

### 个人线：OpenClaw 对照 Muse 的产品需求

使用假邮箱、假日历或模拟服务，不接个人真实账号：

```text
用户通过消息交给一个跨天目标
 → 保存偏好与任务
 → 定时 / 事件触发
 → 生成草稿
 → 请求批准
 → 模拟发送与通知
```

读源码时追：Gateway 身份 / 会话 → 定时触发 → 执行 → 审批 → 结果回传。测试重复事件、跨用户隔离、取消、权限撤销与恢复。

两条线都输出架构图、一次完整时序、概念映射、版本限制与测试证据。现阶段只制定任务，未声称开源项目均原生实现所有步骤或已安全通过。
