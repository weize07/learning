## 1. 为什么有了 SFT，还要学习偏好？

SFT 提供一个示范答案，让模型增加生成示范 token 的概率。但一个问题通常有多个合理回答，质量也可能不同：

- 都正确，但一个简洁清楚，另一个冗长。
- 都有引用，但一个引用真正支持主张，另一个只是堆编号。
- 一个承认资料不足，另一个自信地补出日期。

偏好数据提供的是比较信号：

> 在同样问题和上下文下，回答 A 比回答 B 更符合我们定义的标准。

它不是说 A 每个 token 都唯一正确，也不是自动证明 A 绝对正确。两条都很差时，也能选出相对好的一条，因此需标注绝对质量与不可用情况。

## 2. 三种信号放在一起看

| 数据 / 目标 | 提供什么 | 典型用途 |
|---|---|---|
| SFT 示范 | 条件 x 与目标回答 y | 模仿示范回答 |
| 偏好对 | 同一条件 x、较好回答、较差回答 | 训练排序奖励或直接偏好优化 |
| 可验证奖励 | 测试、规则或环境给出的反馈 | 例如代码测试、数学答案验证、工具任务完成 |

偏好判断可以来自人工、规则或模型，但质量、偏差与适用范围不同。偏好数据可以用于 Reward Model，也可用于 DPO 等方法；不是所有偏好优化都必须先训练奖励模型。

## 3. 一条偏好样本的结构

以给定资料问答为例，以下政策为虚构教学资料：

```json
{
  "id": "pref_001",
  "prompt": {
    "question": "周一提交申请，周四一定完成吗？",
    "evidence": [
      {"id": "D1", "text": "申请处理通常需要三个工作日。"},
      {"id": "D2", "text": "工作日不包括周末及法定节假日。"}
    ]
  },
  "chosen": "资料说明通常需要三个工作日。[D1] 但未说明提交当天是否计入，且未提供节假日情况，不能保证周四完成。[D2]",
  "rejected": "一定周四完成，周一提交后计算三个工作日即可。[D1][D2]",
  "reason": "较好回答保留了“通常”的限定，未编造计时规则；较差回答给出无证据的保证。"
}
```

字段命名是示意，具体训练框架的格式需另外适配。

关键要求：

- 两个回答共享完整条件，包括同一资料与工具结果。
- `chosen` / `rejected` 是相对排序，不表示标签无需审核。
- `reason` 用于追溯标注，通常不直接当作奖励模型输入，以免泄露比较答案。
- 本例的引用存在不等于支持正确，仍要核对每个主张。

## 4. 偏好标准怎么定义？

先定义维度和优先级，而不是让标注者凭“喜欢”：

| 维度 | 有依据问答中的判断 |
|---|---|
| 事实与证据 | 主张是否正确、被给定证据支持 |
| 完整性 | 必要条件是否保留，是否回答问题 |
| 信息不足处理 | 是否明确不确定，而不无依据保证 |
| 引用 | 编号有效，且支持对应主张 |
| 表达 | 清楚、简洁，不用长篇掩盖错误 |

先规定严重错误如何排序。例如不能因语气更好，就让编造事实的回答胜过正确回答。

标注过程应允许平局、无法判断、两者都不可用。标准 pairwise 损失通常只接收有明确排序的样本，其他类别可单独保存、复核或采用专门方法，不能随意强制标签。

候选回答可以来自同一模型的不同采样、不同模型或受控改写。需覆盖真实错误，避免 rejected 总是明显乱码，否则模型可能只学会辨别格式。

对人工或 LLM 标注，匿名、随机展示顺序并抽查一致性；警惕长度偏好、风格偏好、模型自偏好和事实判断错误。互换顺序不应改变合理判断。

## 5. Reward Model 到底是什么？

奖励模型接收条件与一个候选回答，输出分数：

$$
r_\phi(x,y)\in\mathbb R
$$

x 包括问题、证据、历史消息等。y 是完整候选回答。

```text
同一问题与资料 x
     ├→ 回答 y_A → Reward Model → 分数 r_A
     └→ 回答 y_B → Reward Model → 分数 r_B

训练目标：让偏好回答的分数更高
```

常见实现是 Transformer 表示配一个标量打分头，但不是唯一结构。Reward Model 通常是独立的训练角色，不是生成模型 LM Head 词表里的一个特殊 token。

输出分数：

- 不是 next-token 概率；
- 不自动是回答正确概率；
- 不要求位于 0～1；
- 不同奖励模型的原始分数通常不能直接横向比较。

## 6. 怎么用偏好对训练奖励模型？

一种常见 Bradley–Terry 偏好建模假设为：

$$
P_\phi(y^+\succ y^-\mid x)
=\sigma\big(r_\phi(x,y^+)-r_\phi(x,y^-)\big)
$$

$y^+$ 是 chosen，$y^-$ 是 rejected，$\sigma$ 是 sigmoid。

对应损失：

$$
\boxed{
\mathcal L_{\text{RM}}
=-\log\sigma(r_\phi(x,y^+)-r_\phi(x,y^-))
}
$$

如果 chosen 分数比 rejected 高 2：

$$
\sigma(2)\approx0.881,\qquad
\mathcal L_{\text{RM}}\approx0.127
$$

如果顺序反了，分数差为 -2：

$$
\sigma(-2)\approx0.119,\qquad
\mathcal L_{\text{RM}}\approx2.127
$$

这里的概率是模型对“这对回答中哪一个胜出”的预测，不是 chosen 的绝对正确率。

这个损失主要约束分数差：若所有分数同时加常数，差不变，损失也不变。因此不能仅凭一个孤立分数解释绝对质量。

## 7. 有了奖励模型，怎么使用？

| 方法 | 是否更新生成模型 | 作用 |
|---|---|---|
| 候选排序 / best-of-N | 可以不更新 | 生成多个回答，用奖励模型选较好者；增加推理成本 |
| 筛选后做 SFT | 更新 | 选出可靠示范再微调，但仍需检查奖励误判 |
| PPO 等基于奖励的策略优化 | 更新 | 使用奖励训练生成策略，另需控制更新与退化 |
| DPO | 更新，通常不需要单独训练 RM | 直接利用偏好对与策略 / 参考模型概率构造目标 |

不能把 DPO 当成“先训 RM，再照 RM 分数训练”的固定流程。下一专题会比较两条路径。

## 8. 为什么奖励分数越来越高，真实质量可能没变好？

奖励模型是质量的代理，并不等于最终业务目标。优化器会寻找提高这个代理分数的方式：

- 奖励偏爱长回答，模型就输出更多废话。
- 奖励偏爱引用格式，模型堆 `[D1][D2]`，却引用错内容。
- 奖励在某些提示下容易误判，模型生成迎合打分器的回答。

这是 reward hacking / 过度优化代理的一类风险，不代表模型一定有主动欺骗意图。

措施包括更可靠的数据、独立评测、约束优化强度、人工抽查与可验证检查。对给定资料问答，不以平均 reward 代替事实支持、引用正确性和可答 / 不可答评测。

## 9. 数据划分与 RM 评测

按 prompt / 文档 / 相关实体分组划分。同一 prompt 的不同回答对不能随意分别进入训练与测试，否则易高估泛化。

评测可包括：

- 独立偏好对的排序准确率，明确平局处理。
- 按事实、引用、难度与长度差等分层的错误率。
- 候选来源变化下是否仍可靠，是否仅偏好某个模型的写作风格。
- 人工标注一致性，以及模糊 / 不可判断样本比例。

RM 排序准确率高，不自动证明用它优化后的生成模型更好。策略可能产生与 RM 训练分布不同的回答，必须额外测真实生成结果。
