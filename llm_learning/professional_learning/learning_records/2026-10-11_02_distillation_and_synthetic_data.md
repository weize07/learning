## 1. 蒸馏与合成数据不是同一个概念

**蒸馏**：用教师模型的输出或行为指导学生模型。教师常更强、学生常更小，但不要求两者一定如此。

**合成数据**：用模型或程序生成数据，例如问题、答案、改写、工具轨迹或偏好标签。

两者有交集，但不是等号：

- 教师生成回答、学生做 SFT，是一种常见的输出蒸馏。
- 只生成问题，再由人工给答案，也是合成数据，不等于直接蒸馏教师回答。
- 匹配教师概率分布，可以蒸馏，但不一定先保存一个文本答案数据集。

```text
教师提供答案文本 → 学生模仿答案
教师提供概率分布 → 学生匹配分布
学生先生成轨迹   → 教师在学生经历的上下文中提供指导
```

## 2. 路线一：教师生成答案，学生做 SFT

以我们的有依据问答为例：

```text
问题 + 固定证据
       ↓
教师生成回答与引用
       ↓
检查事实、引用和信息不足处理
       ↓
保存可靠示范 → 学生 SFT
```

训练损失仍是正确示范 token 的交叉熵：

$$
\mathcal L_{\text{text}}
=-\sum_t\log p_\theta(y_t^{\text{teacher}}\mid x,y_{<t}^{\text{teacher}})
$$

实际按有效 token / 样本采用明确归约。只监督允许的答案范围，padding 与 prompt 不当作答案目标。

优点是只需要教师文本，适合只能访问生成 API 的情况；不同 tokenizer 的模型也可通过同一文本训练。

局限：

- 只看到教师选出的答案，不知道其他词的概率。
- 教师错误可能进入标签，不能自动视为真值。
- 训练前缀是教师示范，推理时学生用自己的前缀，可能遇到不同状态。
- 很长的示范可能超过学生预算；简单截断可能留下不完整答案。

蒸馏推理过程时，要验证过程与最终结果，不因为写得详细就认为可靠。只模仿“反思、检查”等字样，不保证学生真正具有相应能力。

## 3. 路线二：匹配教师的软概率分布

### 3.1 比只给一个目标 token 多了什么？

假设同一个前缀下，教师对三个 token 的概率为：

| token | 教师概率 |
|---|---:|
| A | 0.7 |
| B | 0.2 |
| C | 0.1 |

文本示范若选 A，普通 one-hot SFT 只把 A 当目标。软分布蒸馏同时告诉学生：B 比 C 更有可能，而不是把所有非 A 选项完全视为同一种目标信息。

这不是每个词都“正确”的概率，而是教师的条件生成分布。

### 3.2 温度与 KL

对教师 logits z_T 和学生 logits z_S，可使用温度 τ：

$$
p_T^\tau(v)=\operatorname{softmax}(z_T/\tau)_v,\qquad
p_S^\tau(v)=\operatorname{softmax}(z_S/\tau)_v
$$

τ 较高时分布更平缓。这里只用于蒸馏分布，不代表推理时必须使用同样的采样温度。

一种常见目标是前向 KL：

$$
\mathcal L_{\text{soft}}
=\tau^2\sum_v p_T^\tau(v)
\log\frac{p_T^\tau(v)}{p_S^\tau(v)}
$$

τ² 是经典设置中的梯度尺度补偿，不是每个实现都必须使用。多个有效位置再按定义归约；教师分布固定，只更新学生。

也可与示范 / 真实标签组合：

$$
\mathcal L=(1-\lambda)\mathcal L_{\text{hard}}
+\lambda\mathcal L_{\text{soft}},\qquad 0\le\lambda\le1
$$

这是候选目标，不是最优配方。两种损失的归约与尺度需匹配，不能只凭 λ 判断实际训练权重。

### 3.3 限制

- 通常需要教师 logits / 概率，仅有答案文本的 API 不一定提供足够信息。
- 直接逐 token 比较要求相同词表与正确的位置对齐；tokenizer 不同不能随意逐维做 KL。
- 教师前向与保存大词表分布增加成本，可研究按需计算等方法。
- 教师分布可能偏差或不适合业务目标；匹配教师不保证超过教师。

KL 方向不同，学习行为也不同。这里选择教师到学生的前向 KL 解释基础，不将所有蒸馏方法都归为这一式子。

## 4. 路线三：On-policy distillation，学生先尝试

先对比两种前缀：

| 方式 | 指导发生在什么前缀？ |
|---|---|
| 教师示范 SFT / 常见离线分布蒸馏 | 教师答案或固定数据的前缀 |
| 学生 on-policy 蒸馏 | 学生当前策略自己生成的前缀 / 轨迹 |

```text
问题 + 证据
       ↓
学生生成回答，进入自己的各种前缀
       ↓
教师在这些前缀上提供概率或相应指导
       ↓
更新学生
       ↓
用更新后的学生再生成
```

目的之一是让训练覆盖学生推理时实际会遇到的状态，减少只模仿教师前缀带来的分布差异。

但学生走入错误前缀后，教师也不能保证无代价地修复。已经写出的错误文字可能无法仅靠续写消除，需要定义纠错、重启或轨迹监督方式。

具体方法可能使用不同 KL 方向、token 级优势或策略优化；“on-policy 蒸馏”不是一个唯一固定损失，也不能简单等同于 GRPO。

例如 [Nemotron-Cascade-2 报告](https://arxiv.org/abs/2603.19220)讨论多领域 on-policy 蒸馏，提供比稀疏终局奖励更密集的 token 级训练信号。它是具体方法，不能直接把本文前向 KL 当作其完整实现。

### 4.1 教师具体提供什么？先看完整词表分布的方式

一种直接的实现是：学生先生成回答，教师随后在学生实际经历的每个前缀上，计算自己的下一 token 分布。教师不必写自然语言评语，也不必另生成完整标准答案。

假设问题是“2+3 等于多少？”，学生的一次回答为“答案是 6”。以下 token 划分与概率仅作示意：

```text
学生生成：
问题 → “答案” → “是” → “6” → 结束

教师评分的其中一个位置：
输入：问题 + 学生前缀“答案是”
输出：下一 token 在整个词表上的概率
```

在数字出现之前：

| 候选 token | 教师概率 | 当前学生概率 |
|---|---:|---:|
| 5 | 0.90 | 0.40 |
| 6 | 0.02 | 0.35 |
| 其他合计 | 0.08 | 0.25 |

教师传递的信息是：“在你走到的这个前缀下，我更倾向接着写 5，而不是 6。”

采用前向 KL 或教师软标签交叉熵时，训练推动学生的整个下一 token 分布接近教师分布，从而在未来遇到类似前缀时更容易选 5。这不修改刚才已经生成的 6；更新后需要重新生成才能观察行为变化。

### 4.2 如何把一条学生回答变成训练信号？

设问题与上下文为 x，学生采样回答为 $y_1,\ldots,y_T$。第 t 个前缀为：

$$
c_t=(x,y_1,\ldots,y_{t-1})
$$

一种示例目标是：

$$
\mathcal L=
\frac1T\sum_{t=1}^{T}
D_{\mathrm{KL}}\left(
p_T(\cdot\mid c_t)\,\|\,p_\theta(\cdot\mid c_t)
\right)
$$

这里 $p_T$ 表示教师分布，T 在求和上限表示回答长度，二者不要混淆。教师保持冻结；学生采样得到的 token 序列作为固定记录，不通过离散采样操作求导，梯度来自学生重新计算的概率。

实际流程：

1. 学生按当前策略采样一批回答，记录 token。
2. 教师在这些回答前缀上前向计算，提供概率。
3. 学生在相同前缀上重新前向计算，构造分布匹配损失。
4. 反向传播更新学生。
5. 用更新后的学生继续采集回答，而不是永久只用第一批旧轨迹。

教师可以一次处理完整学生序列，用 causal mask 并行得到各位置预测；不一定每个 token 都单独调用一次。**教师计算当前位置预测时不能读取未来学生 token**。这与普通 next-token 训练的对齐规则相同。

### 4.3 是否所有方法都提供完整分布？

不一定。要区分三种可能的指导：

| 教师输出 | 学生如何利用 | 边界 |
|---|---|---|
| 完整词表概率 / logits | 在学生前缀上匹配分布 | 需要词表与位置对齐，计算成本较高 |
| 学生已采样 token 的 log 概率 | 与学生概率比较，构造相应采样估计或 token 级信号 | 一个 token 的概率不能直接当作完整词表 KL；方向与采样分布必须按方法推导 |
| 纠正文本、评语或改写答案 | 经验证后组成示范，或构造其他反馈 | 仅生成评语还不是训练更新，需要明确损失和数据转换 |

所以“教师指导”不是一个固定接口；本文第 4.1～4.2 节用完整分布 + 前向 KL 说明最直接的机制，不表示所有 on-policy 蒸馏都这样实现。

它与 RM 给整份回答一个标量也不同：token 分布可以在每一步提供更细的偏好信息，但教师不是可靠性保证，也不自动提供精确的因果信用分配。

### 4.4 教师能处理学生的错误前缀吗？

在“答案是”这个前缀上，教师可以提高 5 的概率。但在学生已经写完“答案是 6”后，正确续写可能是更正，也可能因上下文诱导继续错误表达。

因此不能说教师每一步都会把学生拉回正确答案。需要检查错误前缀下的指导质量，必要时设计纠错轨迹、过滤或重新生成，并在独立任务上验证。若教师只在自己生成的正确前缀上可靠，学生 on-policy 蒸馏的收益也会受限。

## 5. 合成数据怎样生成，才不是只堆数量？

### 5.1 先定义覆盖与正确性

对有依据问答，需要覆盖：

- 直接可答与多片段组合。
- 缺少条件、矛盾资料与版本规则。
- 无关片段、证据顺序与 ID 变化。
- 不同语言、长度与真实用户表达。

先选训练文档组，再生成问题与答案。独立验证 / 测试文档不能被加入生成训练样本的上下文或作为改写种子，避免泄露。

### 5.2 保存来源，区分生成与验证

每条合成样本建议记录：

| 信息 | 用途 |
|---|---|
| 原资料、版本、段落 ID | 判断答案是否有依据 |
| 教师模型与生成参数 | 复现与追踪偏差 |
| 问题、答案、任务类型 | 建立覆盖统计 |
| 检查结果与人工审核状态 | 不把生成成功当正确 |
| 文档 / 实体分组与去重信息 | 防止跨集合泄露 |

同一个模型既生成又审核，可能重复自己的错误。可以结合独立验证器、执行测试、其他模型与人工抽查，但每种验证器也有边界。

### 5.3 过滤不是越严格越好

只保留教师最容易答对的问题，可能让数据偏向简单类型；只筛短答案，也会改变长度与难度分布。

应检查过滤前后的任务覆盖、有效监督 token、错误类型和重复率。发现难题不可靠时，可以修标签或重新采集，而不是让训练集只剩简单题。

## 6. 常见误解与风险

| 误解 | 更准确的说法 |
|---|---|
| 教师大，答案一定正确 | 大模型也会编造事实、误引用 |
| 蒸馏能把所有能力完整复制 | 学生容量、数据覆盖与训练目标都有边界 |
| 长推理示范越多越好 | 要看正确性、预算与目标行为 |
| 生成一百万条就有一百万条新信息 | 可能大量近重复与模板化 |
| 多轮自生成一定持续提高 | 反复学习未经验证的模型输出可能积累错误、丢失分布多样性 |
| 蒸馏后不需要测遗忘 | 新任务与旧能力仍需双评测 |

使用教师服务前核对模型 / 数据许可、服务条款与隐私要求，不能将未经授权的业务资料发送给外部 API。合成也不自动消除原始资料的许可限制。

## 7. 怎么验证蒸馏真的有效？

至少比较：

1. 学生未训练基线。
2. 同学生用可靠示范做 SFT。
3. 新蒸馏 / 合成数据方案，明确新增变化与预算。
4. 教师表现可作为参考，但不是学生必须达到的保证。

保持独立测试，评估：

- 目标任务准确性、证据支持与引用。
- 未见文档 / 实体 / 表达上的泛化。
- 回答长度、格式、拒答倾向等行为变化。
- 旧能力与实际成本。

预算包括教师生成 / 前向、验证成本、学生训练 token 与步数。不能用十倍数据方案与小数据基线的差异，直接证明某个蒸馏目标更优。
