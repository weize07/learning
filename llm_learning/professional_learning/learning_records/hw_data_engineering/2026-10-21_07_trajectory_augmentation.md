# 7. Agent 轨迹增强：增加覆盖，不编造环境

> 2026-10-21 补充；待阅读。未回放真实 Agent，也未执行工具或训练。
> [专题入口](README.md) · 前一章：[多模态数据](2026-10-21_06_multimodal_data_alignment.md) · 下一章：[数据飞轮](2026-10-21_08_data_flywheel_and_capstone.md)

## 1. 是什么：对任务、状态或动作做受约束变化

已有 [Agent 训练数据](../2026-10-19_07_agent_training_data_and_objectives.md)讲了真实 request 视图、监督位置、未来信息泄漏、偏好与恢复。本章只补增强策略和一致性验收。

轨迹可表示为观察、动作、环境变化和反馈的序列。增强不只是改写文字；任何变化都要检查后续状态是否仍成立。

## 2. 为什么要做：成功轨迹不能覆盖真实失败分布

只训练理想路径，模型可能不知道缺字段、工具失败、授权拒绝或状态变化时怎么办。反过来，只增加失败 / 拒绝样本也可能造成过度拒绝。

增强目标应从独立失败分析得出，并同时保留正常成功、边界、恢复和合理终止。不能把“轨迹越长”当作质量越高。

## 3. 怎么做：先规定增强算子和不变量

### 3.1 增强方式

| 算子 | 改什么 | 必须保持或重验什么 |
|---|---|---|
| 表达改写 | 用户请求措辞 | 目标、约束、授权和答案含义不变 |
| 实体替换 | 人名、日期、文件 ID | 工具参数、引用、时区和环境对象同步变化 |
| 干扰注入 | 无关候选或文档 | 真实证据仍存在，不泄露最终答案 |
| 环境扰动 | 暂时失败、缺数据、版本变化 | 后续动作从新状态实际重放 |
| 失败修复 | 从错误决策点改成正确动作 | 丢弃失效后缀，重新获得 observation |
| 学生探索 | 在学生实际遇到的状态请求指导 | 记录行为策略与环境，重新核验结果 |

教学增强不应生成无授权的真实副作用。邮件、交易、文件破坏类场景用受控模拟，不把业务系统当作数据采集试验场。

### 3.2 一条增强契约

至少保存：

- 父任务与父轨迹 ID、原始数据组、增强算子与版本。
- 任务目标、初始环境快照、随机种子和工具 schema 版本。
- 每步模型当时实际可见的上下文、动作与 observation。
- 允许的变化、不变量、受影响的后缀范围。
- 独立 grader 的版本、结果和失败原因。
- 训练用途：SFT、偏好候选、RL 任务或仅供诊断。

环境快照和 request 可能含敏感信息；只保存获准内容。无法复现的外部状态应标为限制，不伪造“已回放通过”。

### 3.3 贯穿例子：拒绝发送之后

原轨迹是“生成草稿 → 请求批准 → 用户拒绝 → Agent 仍请求发送 → 策略阻止”。

可把拒绝后的正确动作改为“保留草稿并如实告知未发送”。但不能继续沿用原来的“发送请求被阻止”结果，因为新分支没有发送调用。

正确过程：

```text
Snapshot before the changed decision
  -> Restore the same visible state
  -> Apply the corrected action
  -> Execute in the controlled environment
  -> Collect the new observation
  -> Verify outcome + intermediate actions
  -> Build the training example
```

若只需要这个决策点的 SFT，可以在正确回答后截取样本，不必编造一段完整工具轨迹；但正确性证据仍要充分。

### 3.4 同一条轨迹不一定适合所有训练目标

| 用途 | 入选条件 | 禁止混用 |
|---|---|---|
| SFT 正例 | 监督动作正确，输入符合当时可见性 | 错误动作不能因最终成功而变正例 |
| 恢复 SFT | 失败历史真实，监督其后的正确恢复 | 将未来结果倒灌进恢复前输入 |
| 偏好对 | 同一决策条件、可比较候选、可靠偏好 | 不同授权 / 环境的答案直接配对 |
| 环境 RL | 任务、环境、奖励与算法采样要求相容 | 任意历史轨迹直接当作当前 on-policy rollout |
| 诊断 / 回归 | 能重现某类问题 | 默认全部回流训练，污染回归集 |

轨迹较长会增加监督 token 和重复前缀；应检查每任务权重、每步权重与预算，不让一个冗长任务支配训练。

### 3.5 划分和质量门禁

先按任务族 / 来源划分，再在训练组内增强；父轨迹和所有变体继承同组。开发坏例可以指导补“同类问题”，不能直接复制为训练数据后仍用原题证明泛化。

门禁至少包括：工具调用 / 结果 ID 成对、参数 schema 正确、时序可见性、状态转移成立、授权一致、终态与严格 grader 一致。终态成功不应抵消中间违规。

## 4. 为什么这么做：增强必须改变有价值的分布

表达改写便宜，但未必增加新的决策能力；环境扰动和学生探索更贴近真实失败，却需要可靠模拟与验证。按失败类别选择算子，而不是为了数量把所有样本改写十遍。

比较无增强、表达增强、状态 / 恢复增强时，应匹配有效训练预算，并用未见任务族测严格成功、恢复、违规尝试、过度拒绝和成本。

## 5. 可选练习

围绕模拟只读工具准备“成功读取、缺字段、暂时失败、权限拒绝”四种状态，为其中一种写增强契约。

通过条件：新分支不复用旧结果；当前输入不含未来判分；派生任务不跨集合；修复动作有独立验证；失败输出保留错误状态，不包装成成功；明确尚未运行的部分。
