# 8. 数据飞轮与综合设计练习

> 2026-10-21 补充；待阅读。本文是可选设计练习，不是已启动的项目或实验报告。
> [专题入口](README.md) · 前一章：[轨迹增强](2026-10-21_07_trajectory_augmentation.md)

## 1. 是什么：反馈驱动下一版数据，不是日志自动回灌

数据飞轮把模型失败转化为数据假设，再用新数据和受控训练验证，只有确认收益后才发布。核心是可归因的闭环，不是采集量不断增长。

```text
Independent evaluation + permitted feedback
  -> Failure attribution
  -> Data hypothesis
  -> Targeted acquisition / repair / synthesis
  -> Quality + governance gates
  -> Versioned data release
  -> Controlled training comparison
  -> Model release or rejection
  -> New independent evaluation
```

## 2. 为什么要做：不是所有坏例都该加数据

| 失败证据 | 优先处理 | 何时才考虑数据 |
|---|---|---|
| 工具 schema 错、资料不可达 | 修接口 / 检索 / 配置 | 工程修复后仍存在稳定行为缺口 |
| 标注互相矛盾 | 修标准与标签 | 有统一规则后扩充 |
| 某语言质量 / 覆盖不足 | 查语言识别、过滤与供给 | 确认缺口后重平衡或补采 |
| 模型不会处理真实恢复状态 | 检查 runtime 与错误契约 | 环境可靠后补恢复轨迹 |
| 视觉答案忽略图像 | 查配对、任务设计与评测 | 补视觉必要、事实可验证的样本 |

已有 [应用评测](../2026-10-11_05_application_evaluation.md)和[Agent 可观测性](../2026-10-19_06_agent_metrics_observability_and_rollout.md)负责诊断基础；这里新增数据、训练、发布之间的版本联系。

## 3. 怎么做：一次迭代只验证明确假设

### 3.1 写清实验问题

例如：“少数语言的文档问答失败，是源文解析损坏，而不是缺少更多同类样本。”

先审查解析产物；若成立，只替换解析策略生成候选数据版本，固定其余处理和训练条件。若一次同时改 tokenizer、去重阈值、模型规模和预算，就无法单独归因于解析。

数据规则会改变保留量：可用同 token 预算比较数据质量，也可研究同采集成本下的产出价值，但这两种问题不能混为一个“公平对照”。

### 3.2 建立版本链

```text
Source snapshot
  -> Processing / policy versions
  -> Dataset manifest + mixture
  -> Training configuration + checkpoint
  -> Evaluation suite + grader versions
  -> Release decision
```

每次失败都能向前定位来源和处理规则；某来源撤回也能向后定位受影响数据 / 模型。数据回退和模型回退是两件事：换回旧数据不会自动恢复已更新的权重。

### 3.3 同时看产能、质量和效用

| 层 | 代表指标 | 易误读之处 |
|---|---|---|
| 生产 | 吞吐、阶段耗时、失败 / 重试、有效 token 成本 | 吞吐高可能只是跳过检查 |
| 质量 | 通过集缺陷、误删、重复、来源可追溯、分层覆盖 | 平均质量高可能牺牲少数语言 |
| 模型 | 同预算目标能力、保留能力、泛化与风险指标 | loss 下降不等于业务能力提高 |
| 闭环 | 问题到数据修复的周期、复发率、可回退性 | 版本数量不等于迭代有效 |

有益的飞轮允许结论为“新数据无收益，拒绝发布”。不能因为数据已生成、成本已投入，就默认继续训练或上线。

### 3.4 跨团队交接

- 数据负责人交付 schema、来源和质量卡，不只交文件路径。
- 算法负责人确认消费格式、预算与效果验收，不只要求“更多数据”。
- 标注 / 领域负责人维护标准和分歧仲裁。
- 平台负责人提供可观测执行、配额与恢复能力。
- 隐私 / 合规负责人确认适用范围和处置要求。
- 发布负责人汇总证据、残余风险与回退方案。

前沿方法也走这条路径：明确问题和机制 → 固定参考版本 → 定义基线与资源预算 → 小规模验证 → 目标规模复核。论文分数不是本地场景已验证收益。

## 4. 为什么这么做：防止反馈自我强化

在线日志受现有用户、模型、曝光策略和工具能力限制，并非天然代表目标世界。只收集当前模型成功样本，会放大已有强项；只追逐已知坏例，又可能遗忘正常能力。

保留独立来源、正常 / 困难分层评测和不参与调参的最终测试。测试集若被用于生成或修复，应退役相应独立性声明，并补新的独立测量。

## 5. 可选综合练习：先设计，不自动开工

**统一场景：为一个支持中英文技术资料的模型，设计小型数据生产方案。** 主线是文本语料与问答；图文、轨迹各做一个小分支，不要求一次训练出全能模型。

数据仅用自拟内容或明确可使用的资料。规模自定，先覆盖失败类型；不使用公司邮件、客户日志或简历中的业务资产。

### 5.1 交付物

| 交付物 | 对应章节 | 最小内容 |
|---|---|---|
| 数据契约与流程图 | 1 | 来源、schema、状态、派生关系和 manifest |
| 去重 / 恢复设计 | 2 | 精确与近重复、跨分片、失败后重跑 |
| 质量与治理卡 | 3 | 通过 / 拒绝 / 隔离、抽查、使用和删除规则 |
| 配方预算表 | 4 | 分语言 / 域 token、曝光、候选对照 |
| 合成验证设计 | 5 | 覆盖、独立校验、误判与成本 |
| 图文样例 | 6 | 正确 / 错配 / 不可答，资产与标签依据 |
| 轨迹增强样例 | 7 | 父组、状态、变换和后缀重新验证 |
| 发布决策模板 | 8 | 数据证据、模型证据、风险、回退 |

### 5.2 验收矩阵：区分可以手查与需要实际执行

| 刺激 | 预期 | 证据方式 |
|---|---|---|
| 相同文档进入不同分片 | 仍能识别，代表选择稳定 | 后续实现后测试；当前先写输入 / 预期 |
| 一条记录解析失败 | 隔离且报告，不丢失计数 | 数据状态清单 |
| 权限未知或来源撤回 | 不发布；可定位受影响派生版本 | 血缘与处置演练设计 |
| 文档被改写 / 翻译 | 与父文档保持同一划分 | 分组清单核对 |
| 过滤器误删某语言 | 分层报告能暴露，阻止盲目放行 | 抽查和阈值依据 |
| Caption 数字与图不符 | 不能只靠主题相似度通过 | 人工 / 规则核验 |
| 轨迹动作改变 | 旧后缀失效，重新验证状态 | 回放设计；未运行则标待验证 |
| 新配方看似更优 | 用固定预算与独立指标复核 | 真实训练 / 评测后才能填写结论 |

工程不变量可设明确零容忍条件，如发布记录无未知权限、无缺失必需字段、无已知跨集合派生组。质量阈值和模型退化预算则需按任务风险、样本量与基线确定，不能随意填一个统一百分比。

### 5.3 学习完成与工程完成分开

能解释设计和取舍，属于理论进展；实现管线并通过故障 / 数据测试，属于工程验证；证明新数据改善模型，必须另有真实对照实验。

当前只提供教材与练习定义。是否进入实现、安装工具、获取数据和启动训练，由后续任务决定，不改变暂停中的 SFT 实验或当前 Agent 设计任务。
