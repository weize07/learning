# 2. 大规模处理、检索去重与评测污染

> [专题入口](README.md) · 前一章：[数据管线](2026-10-21_01_pretraining_data_pipeline.md) · 下一章：[质量治理](2026-10-21_03_quality_validation_and_governance.md)

## 1. 是什么：找重复，不是找“相关内容”

RAG 检索要找能回答问题的文档；去重要找重复内容、模板或派生关系，并决定保留、降权还是隔离。两篇材料讲同一主题，不代表可以互相删除。

| 层次 | 检查对象 | 常见方法 | 主要边界 |
|---|---|---|---|
| 精确重复 | 字节或规范化后的完整内容 | 内容哈希后分组 | 规范化可能误删有意义差异 |
| 词面近重复 | 大部分片段相同的文档 | shingle、MinHash、LSH 后复核 | 依赖分词、长度和阈值 |
| 段落 / 子串重复 | 模板、页脚、大段复制 | 段落哈希、重复子串检测 | 模板相同不等于全文无用 |
| 语义近似 | 改写、翻译、相似指令 | embedding 召回后核验 | 主题相似或关键数字不同，可能不是重复 |
| 评测污染 | 训练与评测的内容 / 派生重叠 | 来源、实体、模板、词面和语义联合审计 | 没检出不等于没有污染 |

## 2. 为什么要做：重复改变有效权重与测量可信度

同一内容出现一百次，不是增加一百份独立知识；它可能抢占预算、放大某来源，并增加记忆风险。训练与测试共享近重复，则可能把记忆当成泛化。

另一方面，简单地“删到重复率最低”也不正确：不同语言的对应材料、必要的规范条款和困难任务可能被误删。目标是减少无效重复，同时保护有用覆盖。

## 3. 怎么做：候选召回、精确核验、全局决策

### 3.1 从 shingle 到 MinHash / LSH

Shingle 是连续的词或字符片段。把文档变为片段集合 $A$、$B$ 后，可计算 Jaccard 相似度：

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}
$$

若 $A=\{a,b,c,d\}$，$B=\{a,b,c,e\}$，相似度是 $3/5$，不是 $3/4$。集合表示会丢掉出现次数；顺序信息只部分保留在连续片段中。中文不能直接假定按空格分词即可。

MinHash 用多个哈希签名近似集合相似度。在理想随机排列假设下，单个签名相等的概率等于 Jaccard 相似度。签名较长通常降低估计方差，但增加存储和比较成本。

LSH 将签名分成 $b$ 个 band，每个有 $r$ 行；任一 band 相同就进入候选。理想独立假设下，相似度为 $s$ 的一对成为候选的概率是：

$$
P(\text{candidate}\mid s)=1-(1-s^r)^b
$$

这是召回概率曲线，不是“超过某阈值必被检出”的保证。实践中先用标注的重复 / 非重复对校准，再选择签名长度、band 和复核规则。

### 3.2 全局去重的数据流

```text
Per-record normalization + signatures
  -> Emit (band_id, band_hash, record_id)
  -> Shuffle candidates across all input shards
  -> Recheck candidate pairs
  -> Build duplicate groups
  -> Choose representatives / weights
  -> Publish decisions + provenance
```

只在每个文件内去重会漏掉跨分片复制。增量批次也要与保留的历史索引比较；规范化或签名版本改变时，需要重建或明确兼容边界。

每个重复组可按可用权限、内容完整性、质量和来源稳定性选择代表；规则需确定性，避免重跑时代表漂移。保留多个来源的血缘，不把其他来源的限制“洗掉”。

**传递性陷阱**：A 与 B 达标、B 与 C 达标，不表示 A 与 C 达标。连通分量便于分组，但“每簇只留一条”可能过删；可改用与代表逐条核验、拆簇或降权。

### 3.3 分布式工程要点

| 问题 | 处理思路 | 必须检查 |
|---|---|---|
| 单文件过大、分片不均 | 按可独立处理的记录 / 字节预算分片 | 最大任务耗时、内存峰值、长尾 |
| 热桶、模板导致候选爆炸 | 标记高频片段，分层处理热桶 | 不得静默截断候选后声称全量去重 |
| 重试导致重复输出 | 固定输入 / 配置身份，临时输出后提交 manifest | 同一逻辑分片只能发布一个有效结果 |
| 部分阶段失败 | 失败分片独立记录，依赖阶段等待完成清单 | 不把“进程退出”当作所有输入已处理 |
| 全局状态过大 | 外部排序、分区索引、分阶段聚合 | 跨分区重复仍能相遇，不能只做局部近似 |
| 删除 / 增量更新 | 更新来源、代表关系和签名索引 | 被删来源不再通过旧缓存或旧版本重新进入 |

Spark / Ray / DataTrove 是执行选择，不是质量保证。先定数据契约与全局操作，再按团队现有栈选工具；不为学习去重先搭集群。

### 3.4 去重与集合划分联动

先按来源、文档族、任务族建立不可跨集合的组，再结合重复关系完善组边界，最后分配 train / dev / test。增强样本继承父组。

对外部 benchmark 单独做污染审计；题面、答案、解析和改写都可能泄漏。只检查完整字符串无法覆盖翻译或模板派生。评测内容仅用于受控的排查，不进入训练生成上下文。

如果后来发现污染，应剔除相关训练数据并重建受影响实验，或重新定义独立评测集；不能仅在报告里减去几道题就保证训练影响消失。

## 4. 为什么这么做：不要把一个近似算法当最终裁决

精确哈希便宜，适合第一层；LSH 避免所有文档两两比较；embedding 可召回改写，但成本更高且易混淆“相似”与“等价”。因此分层处理，并对删除决策做人工抽查，比全量只用一个相似度阈值更可解释。

校准至少包含两组样本：从候选中抽样估计误删风险；从已知重复对和非候选区域独立抽样，检查漏检。只抽算法检出的候选，不能估计全库召回率。

## 5. 可选练习与验收

构造十几条自拟文本，包含完全复制、换行变化、段落复制、否定词变化、关键数字变化和同主题不同事实。

- 相同数据改分片、乱序或重跑，最终保留集合和原因不变。
- 完全重复放在不同分片，仍能检出。
- “允许发送”和“不允许发送”不能因高度相似就直接合并。
- 准备 A-B、B-C 相似但 A-C 不达标的例子，说明聚类策略。
- 报告候选数、核验通过数、删除数、抽查误删与已知重复召回；分母写清楚。
- 任一分片失败时，整版数据不得被标成完整发布。
