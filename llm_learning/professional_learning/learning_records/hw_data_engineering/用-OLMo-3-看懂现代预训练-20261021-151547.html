1. 先分桶，再决定各桶占比

OLMo 3 使用 WebOrganizer 的 24 个主题类别。 FastText 分类器负责判断文档属于哪个主题。 分类器回答“放在哪个桶”，不负责决定“该桶占多少”。 占比由后面的配方实验与优化决定。

2. 方法一：Swarm-based mixing，用一批小模型试配方

这里的 swarm 指一组代理模型实验。 它不是多 Agent 协商，也不等同于粒子群优化算法。

先试多个配方，而非反复训练完整的 7B 模型。 官方说明使用 30M 参数代理模型，每个训练 3B token。 候选比例从围绕自然分布的 Dirichlet 分布中采样。 它能生成一组非负、总和为 1 的权重。 采样分布的设置决定探索有多分散。

例如，某候选提高科技桶，另一候选增加健康桶。 同样的代理训练预算下，比较它们带来的能力变化。 重点不是某个桶自身的训练 loss，而是多项开发评测。

这段其实包含两次学习：先训练语言模型，再学习“配方与成绩的关系”。 前者学的是预测下一个 token，后者学的是预测评测分数。 它们不是同一个模型，也不使用同一种训练数据。

BPB 怎么得到：检查模型给参考文本多大概率

先看直觉：模型越认为参考文本“应该出现”，BPB 就越低。 评测时，给模型题目或前缀，再计算它赋给参考续文的概率。 这里不必先让模型自由生成，再判断整个答案对不对。

设被评分的参考续文为 y1,…,yn，前缀为 c。 单条样本的 BPB 可以写成：

BPB=−∑t=1nlog2⁡pθ(yt|c,y<t)被评分参考续文的字节数

分子是预测这段参考文本的总“意外程度”，单位为 bit。 分母按被评分文本的字节长度归一化，不是除以 token 数。 若只给回答评分，不能把题目的字节数也放入这个分母。 任务如何选择评分片段、如何汇总样本，以其配置为准。

一个可以手算的例子：参考续文只有 AB。 假设 tokenizer 恰好切成 A、B，两字节均参与评分。

  • 模型甲：给 A 的概率是 0.5；看到真实 A 后，给 B 的概率也是 0.5。
  • 模型乙：上述两个条件概率均为 0.25。
BPB甲=1+12=1,BPB乙=2+22=2

因为 −log2⁡0.5=1，而 −log2⁡0.25=2。 甲给同一段参考文本的概率更高，所以 BPB 更低。 这里的 bit 是理想编码长度的量纲，不是实际压缩文件大小。

准确率只问“答对没有”；BPB 还反映给正确目标多少概率。 两个模型都没把参考答案排第一，BPB 仍可能不同。 因此 BPB 不是答对百分比，也不是“这篇训练文档有多好”的分数。 比较候选配方时，要在同一任务和同一评分口径下比较。

答疑：预训练评测是不是只看 BPB？

对 BPB 这一项，你的理解正确；对整个 Base Easy 或全部预训练评测，需要加限制。 前面的讲解聚焦数据配方搜索，不代表预训练只使用一种评测。 要分开三件事：训练用什么损失、选配方看什么信号、最终模型会不会做任务。

1. BPB 与困惑度属于同一类信号，但数值不是同一个东西

二者都来自参考文本的负对数似然。 设评分片段的总负对数似然为 S，使用自然对数。 其 token 数为 N，字节数为 B：

PPL=exp⁡(S/N),BPB=SBln⁡2

PPL 是按 token 平均后取指数；BPB 是按字节平均，以 bit 表示。 对同一评分文本、同一 tokenizer，二者都随总损失降低而降低。 不能把 BPB 的数值直接当成 PPL，也不能不管口径就跨任务比较。

你说的“next golden token 概率”，可以更准确地表述为： 使用真实参考前缀，计算每个正确目标 token 的概率，再汇总。 这通常采用 teacher forcing，而不是沿模型自己生成的前缀评分。 评分片段可以是参考答案、参考解题过程或参考代码，不只是普通文章。

2. Base Easy 不是所有任务都只返回 BPB

官方将 Base Easy 用于小规模实验。 当前公开注册表包含下面四组配置：

配置组 核心评分方式 能说明什么，不能说明什么
math_bpb 数学参考续文的 BPB 给参考解答的概率；不等于自行解题成功率
code_bpb 参考代码的 BPB 给参考程序的概率；该指标不证明生成程序通过测试
qa_bpb 问答参考答案的 BPB 给正确答案的概率；不等于生成回答正确率
qa_rc 包含候选续文打分、选择与准确率 可以判断选项是否选对；不等于自由生成或环境执行

例如 qa_rc 中的 ARC-Easy 使用 acc_per_char。 这里按候选文本的字符长度归一化打分，再判断选中的答案是否正确。 它不是“逐字符答对率”，也不只读取正确选项的概率。 它需要比较候选答案，所以已经包含“是否选对”的离散结果。

不能把整个 qa_rc 都简化成同一指标；它还包含不同任务配置。 这里举 ARC-Easy，是为说明 Base Easy 并非全部只有 BPB。 某个评测运行还可能收集辅助指标；主指标不等于全部执行动作。

证据：四组 Base Easy 配置 · ARC-Easy 的主指标。

4. 为什么选配方时偏好 BPB，却仍要验证任务成功？

小代理模型的任务成功率可能很低，容易难以区分配方。 即使还答不对，给参考答案的概率提高也会反映在损失里。 这是概率指标能提供的细粒度信号，不是成功率的替代定义。

BPB 本身不要求采样长答案或运行生成代码，通常更适合频繁比较。 但它有两个重要边界：

  • 评分时已有正确历史；自由生成时，早期错误会改变后续上下文。
  • 参考文本只是一个解法；不同措辞或不同程序也可能正确。

因此 BPB 下降不保证准确率或执行成功率同步上升。 一个能正常运行的替代实现，也可能与参考代码的措辞差异很大。

最准确的理解是： 用概率损失高效筛选配方，再用选择、生成或执行指标验证目标能力。 本节核对的是公开配置与实现，没有运行模型评测。

广义线性模型是什么：用实验成绩拟合一个小型回归器

现在才轮到第二种模型。 对代码任务，取上表的“配比 → 代码 BPB”作为监督数据。 对数学任务，取相同配比与“数学 BPB”，另外拟合一个回归器。 一个评测任务一个预测器，不是一个训练 domain 一个预测器。

可以先用最熟悉的线性回归理解“拟合”。 假设从实验记录中学到下面这个代码任务预测函数：

BPBˆcode=2−wcode

这是与上表一致的教学函数，不是 OLMo 发布的实际公式。 这里利用了两域比例之和为 1，所以只需一个独立变量。 实际多域模型要考虑整组配比，不能据此忽略其他域。

对尚未训练过的配方“数学 40%、代码 60%”：

BPBˆcode=2−0.6=1.4

这次只计算一个回归函数，没有再训练一个语言模型。 1.4 是预测值，不是新模型已经测出的成绩。 数学任务的预测分数，要由它自己的回归器另算。 后续搜索再综合这些任务分数，并检查数据供给与重复约束。

“广义线性模型”是在这类回归上允许使用连接函数：

g(BPBˆj)=bj+∑iβjiwi

可以理解为：对配比做加权组合，再经函数变换得到预测分数。 系数从已有实验记录中拟合；它不是一个大语言模型。 此式只解释模型类别，不指定 OLMo 的实际连接函数或拟合参数。 官方混合说明未在该段给出这些细节，不能凭“GLM”三个字补造。

整段话翻译成白话： 先花钱训练一些小模型，测出“哪些配方考得怎么样”。 再拟合几个便宜的小函数，估计更多新配方的成绩。 筛出值得尝试的配方后，仍要真实训练来验证。

依据：官方配方回归说明。

2.1 一次候选配方实验，究竟输入和输出什么？

把全部主题比例写成一个向量 w。 每个分量是某个主题的 token 占比，所有分量相加为 1。 改的是训练数据的组成，不是分别训练一个科技模型和一个健康模型。 每个代理模型都训练一份完整混合，只是各桶比例不同。

以三个合并后的主题桶为教学例子：

w=(0.30,0.20,0.50)

三个分量依次代表科技、软件开发和其他主题。 这不是 OLMo 实际采用的三域配方，只用来解释实验单位。 若沿用官方每个代理模型 3B token 的预算，则计划消费：

3B×w=(0.9B,0.6B,1.5B)
实验环节 一次实验应记录什么
输入配方 全部主题权重，以及对应的数据池版本
控制条件 相同代理模型规模与训练预算；记录训练配置
实际训练 一个模型消费完整混合，而非每个桶各训一个模型
开发评测 一组任务各自的 BPB，保留能力间的差异
回归样本 整组配方 w → 各任务表现 ℓ1,…,ℓJ

官方将代理实验数量设为约 domain 数的 5 倍。 24 个主题对应约 120 次实验，这是按规则估算，不是训练日志计数。 每次都需真正训练代理模型；只是比反复训练完整 7B 模型便宜。

Dirichlet 分布让候选权重满足非负且总和为 1。 它围绕自然分布探索，不代表每次只能小幅修改一个 domain。 集中程度控制探索范围；本页不假定官方使用了某个未核对的参数值。

3. 怎样从预测结果得到新比例

下面是便于理解的数学表达，不是优化代码的逐行复刻。 设 wi 是第 i 个 domain 的 token 占比。 设 ℓˆj(w) 是第 j 个任务的预测 BPB。 搜索目标可以写成：

w⋆=arg⁡minw⁡1J∑j=1Jℓˆj(w)

也就是找一个使多任务平均预测损失较低的配方。 同时满足：

wi≥0,∑iwi=1,Bwi≤rimax⁡Ui
符号 含义
B 目标混合的总 token 预算
Ui 该域可供采样的 token 量
rimax⁡ 允许的最大重复曝光倍数
Bwi 希望从该域获得的训练 token 量

最后一个约束防止小数据域被无限重复。 官方方案使用约 6T 的目标预算。 重复上限依域和可用数据而定，说明中给出 4–7 倍范围。 这不是所有数据桶都必须重复相同次数。

例如，科技桶上调不是因为它的当前 loss 最大。 而是代理实验预测：增加其占比，更有利于目标评测。 噪声域也可能有高 loss，所以“哪里 loss 高就多喂哪里”不可靠。

预测器只是近似，不能替代真实训练验证。 官方还报告了 1B 模型上的验证，且部分任务仍会退化。 平均收益不意味着每个 domain、每种能力都获益。

3.1 回归预测器如何让搜索变便宜？

得到上述实验记录后，为每个任务单独拟合一个函数：

ℓˆj(w)=fj(w)

这里输入是完整配比向量，不是某个 domain 的单独分数。 提高科技占比时，至少另一个桶需要减少。 模型学到的是这种预算取舍与评测表现之间的经验关系。

搜索器可反复提出新权重，用回归器估计效果。 数据供给或重复约束不满足的候选，不能作为可用配方。 预测平均损失更低，只说明“值得验证”，不等于实测获胜。

预测器不是给每个 domain 发一个固定的价值分。 某种数据是否有用，还取决于其他数据的比例和评测目标。 线性或广义线性近似也不能保证捕获全部交互。 离已测试配方很远的候选，尤其需要真实训练复核。

开发评测定义了这里的“好配方”。 若目标任务改变，原来的最佳权重也可能不再合适。 反复用来选权重的评测集，不能再称为未见的最终测试集。

4. 方法二：Conditional mixing，增量加入新来源

如果后面才拿到高质量 PDF，不必重新搜索所有旧桶。 可以将已优化的旧配方合为一个“虚拟 domain”。 固定旧桶之间的相对比例，不固定各桶最终的绝对份额。

设旧组内部比例为 ai，新一轮给旧组的总份额为 g：

wi=gai

剩余份额由新加入或发生变化的来源分配。 这样既保留已有实验成果，又减少搜索维度。 代价是冻结旧比例，可能错过新来源加入后的更好组合。

教学示例，不是 OLMo 的真实配方： 旧组内两个桶占 60% 和 40%。 如果新一轮给旧组 80%、新 PDF 20%，则最终比例为：

(0.8×0.6,0.8×0.4,0.2)=(0.48,0.32,0.20)

官方说明记录了三轮衔接：

轮次 搜索内容 固定或承接的部分
第一轮 DCLM-Baseline 网页的 24 个主题比例 从网页自然分布出发
第二轮 StackEdu 内部的编程语言比例 本轮固定 web:code 为 75:25
第三轮 纳入 PDF 的 WebOrganizer 主题桶 条件化承接此前的配方

75:25 是第二轮的实验设置，不是最终全库网页 / 代码比例。 这也解释了为什么前面的来源图不能由某轮中间权重直接推算。

5. 方法三：Quality-aware upsampling，把比例变成数据

比例确定后，还要解决“这个 domain 具体抽哪些文档”。 OLMo 3 不只是均匀抽样，也不只是保留固定的最高分区间。 它为各主题构造“质量分位 → 采样倍数”的曲线。

质量区域 允许的处理方式 作用
低质量区 少采或不采 减少低价值内容
中间区 按预算保留或重采样 补足覆盖与供给
高质量区 较高频率重采样，但受上限约束 在预算内增加优质内容曝光

曲线需同时满足目标 token 量、重复上限和单调性约束。 质量更高的桶不应因此得到更低的采样倍数。 具体分桶方式在下一节展开。

对某个 domain，所需的平均曝光倍数为：

r‾i=BwiUi

教学例子：总预算 100B，目标域占 20%，可用内容为 10B。 该域需贡献 20B token，平均曝光倍数就是 2。 这不代表每篇文档机械复制两次。 可以让低质量桶少出现，高质量桶多出现。

实际发布时还要检查 token 占比。 按文档条数采样，可能因文档长短不同而偏离目标配方。 重复采样增加曝光，不会创造同等数量的新知识。

5.1 将“该域占 20%”落实为可执行采样

沿用前面的教学预算：总量 100B，该域要贡献 20B token。 假设它的可用内容共 10B，分成以下三个质量区域。 下面按可用 token 数设定，不把文档分位当成 token 分位。

这个示例可以用以下曝光倍数实现：

4B×0+5B×2.6+1B×7=20B

该域的平均曝光为 2 倍，高质量区的曝光更高。 它同时满足本例的目标量、单调性和 7 倍上限。 这些数值是教学构造，不是 OLMo 发布的质量曲线。

2.6 倍是桶级平均或期望曝光，不是复制“0.6 篇文档”。 具体执行可用重复遍历加部分抽样，再核对实际 token 数。 文档长短、抽样随机性和截断会使实测比例偏离目标。

至此，三层决策串起来了： 配方实验给 domain 分预算，质量曲线分配桶内曝光，采样器产出训练混合。 分类器负责分桶；它并不直接决定最终训练占比。

6. 这是离线选配方，不是默认在大模型训练中实时调权

本节描述的主线是：训练代理模型、选配方、构造混合，再训练目标模型。 “新增数据后重选配方”不等于“每个训练 step 自动改比例”。 质量分桶和上采样也不等于根据实时梯度更新 domain 权重。

因此，理解这一方案时要区分三个决策： 主题分类决定桶；代理评测决定桶的预算；质量采样决定桶内的曝光。

资料依据：

  • 官方混合方法：Swarm、Conditional mixing 与质量重采样。
  • 完整 24 类及自然 / 优化比例。
  • 分类与质量分桶的处理说明。
D

真正的采样单位：来源 × 主题 × 质量

同一主题里，网页质量仍可能相差很大。 因此它还按质量分数，把主题桶细分成约 20 个分位桶。 每个桶对应约 5 个百分点的质量分位区间。 质量分位不是“内容正确的概率”。

可把一个采样单元理解为： “网页来源中的科技主题、质量位于该主题前 5% 的文档”。 这只是分桶示例，不代表全部前 5% 文档都使用相同权重。

配比并非纯靠人工拍定。 官方先训练多个 30M 参数代理模型，每个使用 3B token。 再依据开发评测拟合“配比到效果”的关系，搜索受约束的方案。 高质量桶可被上采样，但有重复上限和数据供给约束。 代理模型上的优胜配方，仍需在更大模型上验证。

改变的是模型看哪些内容、看多少次，不一定改变学习目标。

来源：分类与质量分桶 · 配比优化与重采样

E

是的：主流生成式基座仍在预测下一个 token

OLMo 3 模型卡明确把它定义为自回归 Transformer 语言模型。 对 token 序列 x1,…,xL，基础预测目标是：

pθ(x1,…,xL)=∏t=1Lpθ(xt|x<t)

主损失是目标 token 的负对数似然，也就是交叉熵：

ℒNTP=−1L∑t=1Llog⁡pθ(xt|x<t)

第一个位置使用起始条件；实现还会处理边界、mask 和辅助正则项。 上式表示核心目标，不声称完整训练损失只有这一项。

下面按词展示右移关系，不是实际 tokenizer 的切分结果：

  • 看到起始标记，预测“北京”。
  • 看到“北京”，预测“是”。
  • 看到“北京 是”，预测“中国”。
  • 后续位置沿同一规则学习。

训练时通常同时计算多个位置的损失。 Causal mask 阻止当前位置读取未来 token。 Teacher forcing 使用真实前缀，不必先逐字生成整篇再训练。 普通自回归推理则逐步追加模型生成的 token。

网页、代码、论文都能提供这种监督。 下一 token 就来自原文本，不要求人工先制作问答标签。 这就是自监督学习；它不等于完全没有数据筛选或人工审核。

来源：模型类型与公开实现入口

F

“现在”的变化在哪里：数据与阶段更复杂，目标未必换了

同样的 next-token 目标，可用于通用语料、代码、教材和推理文本。 模型要降低长距离预测错误，就需要利用上下文中的结构和规律。 但目标相同，不保证模型自然获得可靠推理或事实正确性。

阶段 主要变化 与自回归的关系
主预训练 大规模通用混合 OLMo 3 使用因果语言建模
Mid-training / 长上下文 数据配方、难度、长度与训练日程 不必因此换成非自回归目标
SFT 输入协议与监督位置 常仍用 next-token 交叉熵
DPO / RL 偏好或奖励驱动的优化 模型仍可自回归生成，但损失不再只是模仿目标 token

因此，“会思考”不意味着“预训练已不用 next-token prediction”。 也不能反过来说所有语言模型都必须自回归。 例如 LLaDA 代表扩散语言模型路线，不能归为同一套因果预测目标。 这里的“仍是主流”限定为公开的生成式 decoder-only 基座。

答疑：编程能力不是到 SFT、DPO 才增强吗？

后训练能增强能力，不代表此前完全没有

预训练模型已经可以生成代码，评测器可以运行它生成的程序。 这不要求模型会调用测试工具，更不要求模型会根据报错修复。 前面“生成代码并运行测试”说的是评测流程，不是 Agent 工作流。

1. 预训练已经能学代码，未必先学会聊天

代码语料不仅有语法，还包含函数、注释、文档和测试示例。 学习这些序列的 next-token prediction，也能学到代码结构与条件关系。 这不保证程序正确，但足以让“代码补全是否正确”成为可测问题。

教学例子：提供下面的函数签名和说明，让模型继续写函数体。

基座模型可以尝试续写 return a + b。 外部评测器随后用测试用例检查结果。 模型不需要先理解“你是编程助手”，也不需要自己启动解释器。 例子只说明任务形式，不是声称某个 checkpoint 已通过该测试。

自然语言指令也可转成函数说明或通过 few-shot 示例引出补全。 因此，Base 模型的评测提示不一定采用聊天模型的指令模板。

2. 谁运行测试：两种流程不要混淆

这是普通的代码生成评测。 在这个流程里，测试结果不必反馈给模型，模型也不需要修复。 模型权重保持不变；评测不是一次训练更新。

Coding Agent 则是另一种要求：

这里除了写代码，还需要选择工具、维护状态和处理失败。 这些能力更依赖适配的后训练数据，以及可靠的运行框架。 即使是 Agent，也由工具和运行环境执行程序，不是语言模型本体执行。

3. 各训练阶段分别怎样增强？

阶段 学习信号 对编程能力的影响与边界
预训练 / 继续预训练 代码、文档、说明与实现中的 token 关系 建立代码知识和生成能力；不只学语法
SFT 任务到正确回答、程序或工具轨迹的示范 改善指令遵循、输出形式和解题策略；也可学新技能
DPO 同一条件下 chosen / rejected 的比较 增强数据偏好的行为；提升什么取决于偏好标签
执行反馈 RL / RLVR 生成程序后，按测试或验证结果给奖励 更直接优化可验证结果；仍受测试覆盖和奖励设计限制

DPO 不天然等于“训练程序正确性”。 如果偏好对只区分风格，就没有直接比较功能正确性。 如果偏好对由可靠测试筛选，则可以传递正确性信号。 测试可用于离线制作偏好数据，但 DPO 损失本身不要求运行程序。

也不能把 SFT 说成只是“解锁已有能力”或“统一格式”。 有针对性的示范能够教会新行为，但不保证所有任务都提升。 编程收益可以来自预训练数据、继续预训练、SFT 或 RL 的变化。 不能仅凭阶段名称，就认定大部分收益一定来自 SFT / DPO。

4. 为什么还要在预训练后测代码执行成功率？

因为要知道：当前基座已经具备多少能力，数据和训练是否真的改善了它。 之后再比较后训练模型，才能看到后训练新增了什么。

如果只有 BPB，就可能漏掉“参考代码概率变高，但生成程序仍不正确”的情况。 执行评测因此可以提前使用，不必等模型已经很强才测。 大规模使用 BPB 筛配方，与关键 checkpoint 做执行评测并不矛盾。

对比前后模型时，要说明 prompt、解码预算与测试环境是否一致。 若 Base 用代码补全、Instruct 用聊天提示，应披露协议差异。 不同提示下的分数差，不能全部归因于模型权重改变。

依据：Base 模型评测入口 · HumanEval 生成与外部测试实现。 上述流程与函数示例用于讲解，没有运行模型、代码测试或训练。
