# 6. 多模态数据与跨模态对齐

> 2026-10-21 补充；待阅读。图文例子为自拟场景，未下载图像或训练视觉语言模型。
> [专题入口](README.md) · 前一章：[合成验证](2026-10-21_05_synthetic_data_verification.md) · 下一章：[轨迹增强](2026-10-21_07_trajectory_augmentation.md)

## 1. 是什么：既要模态可用，也要对应关系成立

多模态数据不是“文字旁边放张图”。训练样本需要说明图像、文字、音频、视频与标签在内容、位置或时间上如何对应。

岗位中的“跨模态亲和”没有在说明里给出统一指标。本专题把它落实为可检验的对齐质量和下游效用，不把某个相似度分数冒充该词的唯一定义。

| 数据形式 | 关系 | 典型质量问题 |
|---|---|---|
| 图文对 | 文本是否描述图中可见内容 | 错图、泛泛 caption、幻觉细节 |
| 视觉指令 | 问题、图像与答案是否相容 | 答案只靠语言先验，根本没看图 |
| 交错图文 | 多段文本、多个图像的顺序和引用 | 图号错位、上下文丢失、训练截断 |
| 音频 / 转写 | 语音、文字、说话人和时间 | 转写错误、说话人归属错、时间偏移 |
| 视频 / 文本 | 帧、事件、时序、音轨与描述 | 漏关键帧、先后颠倒、音画不同步 |

## 2. 为什么要做：对比对齐不等于细节正确

一张显示“销售额 12 万”的图，配文“这是销售图表”，可能语义相似度很高，却没有监督数字读取；若配文写“销售额 21 万”，主题仍然相同，但关键事实错误。

因此图文相似度可用于候选筛选，不能替代 OCR、数量、空间关系和证据支持检查。图像清晰也不保证 caption 正确，caption 正确也不意味着覆盖了任务所需细节。

## 3. 怎么做：从一种模态组合起步

### 3.1 最小图文管线

```text
Permitted image + text sources
  -> Decode / integrity checks
  -> Provenance + pair identity
  -> Image and text duplicate grouping
  -> Pair alignment + support checks
  -> OCR / spatial / task-specific validation
  -> Split by source family
  -> Model-specific encoding + length checks
  -> Versioned dataset + sliced evaluation
```

最小练习先做图文，不同时引入视频和音频管线。但从开始就保留模态身份和血缘，避免以后只能靠文件名猜配对。

### 3.2 一条样本应保留什么

| 字段组 | 必要信息 |
|---|---|
| 身份与来源 | `pair_id`、图像 / 文本来源、父样本、使用限制 |
| 模态特征 | 图像尺寸、方向、解码状态、文本语言；音视频还需时间基准 |
| 任务 | caption、OCR、问答、定位或多图推理，不能混成一个模糊标签 |
| 标注依据 | 对应区域 / 页码 / 时间段、答案依据、人工审核状态 |
| 变换 | 裁剪、缩放、旋转、翻译、caption 重写及其版本 |
| 数据隔离 | 原始资产组、派生组、划分与重复簇 |

若裁剪去掉了被问到的物体，原答案就可能失效；图像增强必须同步变换框、坐标和标签，并重新检查任务是否仍可解。

### 3.3 图文对比学习需要知道的最小原理

图像编码器和文本编码器把两种模态映射到可比较的向量空间。对一个 batch，构造相似度矩阵：

$$
S_{ij}=\frac{v_i^\top t_j}{\tau}
$$

这里假设向量已归一化，$\tau>0$ 为温度。匹配图文是正例，batch 中其他配对常用作负例；若多段文字其实都描述同一张图，简单把其他配对全当负例会产生假负例。

这个目标有助于全局对齐，不自动教会细粒度 OCR、复杂指令或长程推理。视觉指令训练通常还有生成目标，其数据和评测要另行设计。

### 3.4 分别检查资产、配对和标签

- 资产层：损坏、分辨率不足、方向错误、敏感信息、不可用来源。
- 重复层：字节哈希捕捉相同文件；感知哈希或特征召回用于近似图像，再核验。
- 配对层：错配、泛化过度、文字只描述网页而非图片、多图索引错误。
- 标签层：数量、颜色、空间关系、文字内容和答案支持。
- 数据集层：来源 / 类别偏差、模板重复、文字捷径和跨集合泄漏。

同一图的不同压缩、裁剪、caption 和问答通常应作为相关组隔离；不能随机按“图文对”拆分就宣称未见图像泛化。

### 3.5 怎样验证模型真的使用了图像

固定任务，比较正常图像与缺图、错图、受控遮挡的表现，并分别分析需要视觉证据和不需要视觉证据的题目。

这些干预只是诊断，不直接证明完整视觉理解；缺图也可能改变输入分布。还应使用答案随图像内容变化、语言表面形式相近的受控对照。

过滤方案比较时，固定模型起点、训练预算与图像分辨率 / 处理配置。只报文本 token 相等不足以证明多模态计算预算相等。

### 3.6 音视频的额外边界

音频需固定采样率、声道、转写和说话人规则；时间戳要有统一单位。视频需记录帧采样策略、帧时间与音轨时间，检查关键事件是否被采到。

提高抽帧频率增加成本，却不保证标签更准确；把未来帧放到只允许过去信息的任务中，还会产生时序泄漏。音视频扩展需单独的同步和时序验收。

## 4. 为什么这么做：多指标保留真实任务覆盖

只用全局图文分数，容易筛出“看起来相关”的样本，误删文字密集、罕见对象或专业图表。先按任务定义质量，再分层校准，比一刀切分数阈值更能保护目标能力。

## 5. 可选练习

用自制图表和说明构造：正确配对、错图、数字错误、证据不足、裁剪后不可答五类样本。

通过条件：来源和资产可追踪；能区分主题相关与事实支持；同图衍生样本不跨集合；裁剪后重验答案；评测单列 OCR / 数量 / 空间关系，不只有总体分数。
