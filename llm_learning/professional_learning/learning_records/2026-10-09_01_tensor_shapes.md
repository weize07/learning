## 1. 前置练习：张量的轴、行列与 Attention 矩阵乘法

### 1.1. 先纠正一个容易混淆的形状

常见的两种形状是：

$$
\underbrace{[B,n,d_{\text{model}}]}_{\text{隐藏状态或合并投影}}
\qquad
\underbrace{[B,h,n,d_{\text{head}}]}_{\text{拆头后的 Q、K、V}}
$$

不是通常给每个头都分配一个完整的 $d_{\text{model}}$。本节先采用标准 MHA：

$$
d_{\text{model}}=h\,d_{\text{head}}
$$

| 符号 | 数的是什么？ | 是否通常作为注意力矩阵的行列？ |
|---|---|---|
| $B$ | 样本数 | 否，先选哪条样本 |
| $h$ | 头数 | 否，再选哪个头 |
| $n$ | token 位置数 | 是，Q / K / V 矩阵的行数 |
| $d_{\text{model}}$ | 每个 token 的完整隐藏特征数 | 输入矩阵的列数 |
| $d_{\text{head}}$ | 每个 token 在某个头内的特征数 | 每头 Q / K / V 的列数 |

**四维张量不是一个“有四种行列”的矩阵。** 对常见 batched matmul，前面的轴用于组织多个矩阵，最后两个轴才是参与这次乘法的行、列。

### 1.2. 一个 token 是行向量还是列向量？

两种数学约定都可以。本讲义使用 **token 按行排列** 的约定：

$$
X=
\begin{bmatrix}
x_{0,0}&x_{0,1}&x_{0,2}&x_{0,3}\\
x_{1,0}&x_{1,1}&x_{1,2}&x_{1,3}\\
x_{2,0}&x_{2,1}&x_{2,2}&x_{2,3}
\end{bmatrix}
\in\mathbb R^{3\times4}
$$

- 三行：三个 token。
- 四列：每个 token 的四个特征。
- 第一个 token 对应第一行，数学上可视为 $1\times4$ 行向量。

单头投影输出宽度若为 2：

$$
\underbrace{x_i}_{1\times4}
\underbrace{W}_{4\times2}
=\underbrace{q_i}_{1\times2}
$$

对整段序列一起算：

$$
\underbrace{X}_{3\times4}
\underbrace{W}_{4\times2}
=\underbrace{Q}_{3\times2}
$$

投影修改特征宽度，没有将三个 token 合成一个 token。

注意数组索引与数学形状的区别：在 NumPy / PyTorch 中，`X[i]` 通常是形状 `[4]` 的一维数组，没有行列方向；`X[i:i+1]` 才保留 `[1,4]` 的二维行形状。不能把所有一维数组都直接当成二维列向量。

### 1.3. 矩阵乘法的唯一核心规则

$$
\boxed{
[m,k]\ @\ [k,p]\ \longrightarrow\ [m,p]
}
$$

左右矩阵的内侧维度必须匹配；输出保留左边的行数和右边的列数：

$$
C_{ij}=\sum_{r=1}^{k}A_{ir}B_{rj}
$$

**一个输出格子 = 左边一行与右边一列的点积。** 相同形状的两矩阵不能因此随意做矩阵乘法；逐元素相乘是另一种操作。

对 batched matmul，本节的 batch / head 轴相同，逐样本、逐头分别应用这个规则：

$$
[B,h,m,k]\ @\ [B,h,k,p]
\ \longrightarrow\ [B,h,m,p]
$$

这里没有沿 $B$ 或 $h$ 求和，不会混合不同样本或不同头。投影矩阵 $W$ 是二维时，则可以在各样本间复用：

$$
[B,n,d]\ @\ [d,d']
\ \longrightarrow\ [B,n,d']
$$

通用库还支持某些前导轴广播，但形状“能广播”不等于语义正确；先理解这里的同样本、同头配对即可。

### 1.4. 从输入到拆头：为什么需要交换轴？

先暂时忽略 B，只看一条样本。它有 **3 个 token、2 个头，每个头的 query 是 2 维**。

**一句话：原来按 token 组织数据，为了方便各头独立做矩阵乘法，改成按 head 组织数据。**

#### 1.4.1. 第一步：投影结果按 token 排列

合并 Q 投影输出为 $[n,d_{\text{model}}]=[3,4]$：

| token | 头 0 的两个数 | 头 1 的两个数 |
|---|---|---|
| token 0 | 1，2 | 3，4 |
| token 1 | 5，6 | 7，8 |
| token 2 | 9，10 | 11，12 |

这里还没有做任何交换。每行是一个 token，它的四个数中，前两个属于头 0，后两个属于头 1。

#### 1.4.2. 第二步：reshape 只把每个 token 的 4 个数分成两组

从 $[n,4]$ 变成 $[n,h,d_{\text{head}}]=[3,2,2]$：

```text
token 0
    头 0：[1, 2]
    头 1：[3, 4]

token 1
    头 0：[5, 6]
    头 1：[7, 8]

token 2
    头 0：[9, 10]
    头 1：[11, 12]
```

读取顺序是：**先选 token → 再选 head → 再选特征**。

#### 1.4.3. 第三步：交换 n 和 h，改成先选 head

同一份数据，改成 $[h,n,d_{\text{head}}]=[2,3,2]$：

```text
头 0
    token 0：[1, 2]
    token 1：[5, 6]
    token 2：[9, 10]

头 1
    token 0：[3, 4]
    token 1：[7, 8]
    token 2：[11, 12]
```

读取顺序变成：**先选 head → 再选 token → 再选特征**。

例如 `[7,8]` 一直属于“token 1、头 1”，交换轴并没有把它分给别的 token 或头，只是改变访问它时先选哪个轴。

#### 1.4.4. 为什么这种顺序方便计算？

因为每个头都需要自己的“所有 token 的 query 矩阵”。现在选定头 0，就能直接得到：

$$
Q^{(0)}=
\begin{bmatrix}
1&2\\
5&6\\
9&10
\end{bmatrix}
\in\mathbb R^{3\times2}
$$

选定头 1，得到：

$$
Q^{(1)}=
\begin{bmatrix}
3&4\\
7&8\\
11&12
\end{bmatrix}
\in\mathbb R^{3\times2}
$$

最后两轴刚好是 **token 行 × 特征列**，可以对各头分别计算 $Q^{(i)}(K^{(i)})^{\mathsf T}$。放回 batch 后就是：

$$
[B,n,h,d_{\text{head}}]
\ \xrightarrow{\text{交换 token 与 head 轴}}\
[B,h,n,d_{\text{head}}]
$$

**不是 Attention 在数学上必须使用这个轴顺序。** 可以保留其他布局，用索引或指定轴的运算得到相同结果；这里换轴是为了适配常见“最后两轴作为矩阵”的批量乘法写法。

#### 1.4.5. 为什么不能用一次 reshape 代替交换轴？

在这个例子的原始顺序中，数字依次为 `1,2,3,4,5,6,...,12`。直接 reshape 成 `[2,3,2]`，会把前 6 个数全放进“头 0”：

```text
错误的头 0：
token 0：[1, 2]
token 1：[3, 4]  ← 原本是 token 0、头 1 的数据
token 2：[5, 6]  ← 原本是 token 1、头 0 的数据
```

所以两个操作的职责不同：

> **reshape：把一个 token 的特征分成几个头。**  
> **换轴：把分好的数据从“按 token 看”改成“按 head 看”。**

### 1.5. 固定样本和头，先看一个二维 Attention

选定某条样本、某个头后，Q、K、V 都是 $3\times2$ 矩阵。为了看清乘法，取：

$$
Q=
\begin{bmatrix}
1&0\\0&1\\1&1
\end{bmatrix},
\qquad
K=
\begin{bmatrix}
1&2\\3&4\\5&6
\end{bmatrix}
$$

Q 与 K 的每一行分别是某个 token 的 query 与 key。为了让每个 query 匹配每个 key，需要：

$$
\underbrace{Q}_{3\times2}
\underbrace{K^{\mathsf T}}_{2\times3}
=
\begin{bmatrix}
1&3&5\\
2&4&6\\
3&7&11
\end{bmatrix}
$$

结果的轴含义变了：

- 行：哪个 query 位置在寻找信息。
- 列：与哪个 key 位置匹配。
- 格子 $(i,j)$：query $i$ 与 key $j$ 的点积。

例如最后一行、第二列是 $[1,1]\cdot[3,4]=7$。此时最后一维不再是“特征”，而是“key 位置”。

再除以 $\sqrt{2}$、加 mask，沿每行的 key 维度做 softmax，得到 $A$，形状仍为 $3\times3$。

接下来：

$$
\underbrace{A}_{3\times3}
\underbrace{V}_{3\times2}
=\underbrace{O}_{3\times2}
$$

这次相乘的内侧 3 对应 key / value 位置，求和后不再保留；输出的行是 query 位置，列是 value 特征。

例如某一行权重为 $[0.2,0.3,0.5]$，则：

$$
o_i=0.2v_0+0.3v_1+0.5v_2
$$

不是让三个 token 共用一个输出：每个 query 行都有自己的权重与输出向量。

### 1.6. 放回 B、h：完整形状链

| 步骤 | 运算与结果形状 | 被求和的轴 |
|---|---|---|
| 输入投影 | $[2,3,4]@[4,4]\to[2,3,4]$ | 输入特征 |
| 拆头、交换轴 | $[2,3,4]\to[2,3,2,2]\to[2,2,3,2]$ | 无 |
| K 最后两轴转置 | $[2,2,3,2]\to[2,2,2,3]$ | 无 |
| $QK^{\mathsf T}$ | $[2,2,3,2]@[2,2,2,3]\to[2,2,3,3]$ | 每头 Q/K 特征 |
| 缩放、mask、softmax | $[2,2,3,3]\to[2,2,3,3]$ | 不消除轴；softmax 沿 key 轴归一化 |
| $AV$ | $[2,2,3,3]@[2,2,3,2]\to[2,2,3,2]$ | key / value 位置 |
| 合并头 | $[2,2,3,2]\to[2,3,2,2]\to[2,3,4]$ | 无 |
| 输出投影 | $[2,3,4]@[4,4]\to[2,3,4]$ | 合并后的头特征 |

K 的“转置”只交换最后两个轴，不是将 B 或 h 一并倒过来。合并头也要先把输出从 `[B,h,n,d_head]` 调整回 `[B,n,h,d_head]`，再合并最后两个轴。

在 PyTorch 等库中，交换轴后的内存未必连续；代码里通常使用合适的 `reshape`，或先变为连续布局再 `view`。这属于存储细节，不改变上述数学含义。

### 1.7. 为什么 decode 的分数矩阵不是方阵？

更一般地，设 query 数为 $n_q$，key / value 数为 $n_k$：

$$
[B,h,n_q,d_h]\ @\
[B,h,d_h,n_k]
\ \longrightarrow\
[B,h,n_q,n_k]
$$

$$
[B,h,n_q,n_k]\ @\
[B,h,n_k,d_v]
\ \longrightarrow\
[B,h,n_q,d_v]
$$

完整 self-attention 常有 $n_q=n_k=n$，但使用缓存的单 token decode 通常是 $n_q=1$、$n_k=T$：

$$
[B,h,1,d_h]@[B,h,d_h,T]\to[B,h,1,T]
$$

所以“一行”表示当前 query，“T 列”表示它可以匹配的历史与当前位置。后续 GQA 的 KV 头数不同，还需要按组映射，不能直接套用同头数乘法。

### 1.8. 可选练习：先数轴，再算内侧维度

2. 采用 3 个头，每头维度是多少？reshape 和交换轴后的形状分别是什么？
3. 拆头后的 Q、K 做 $QK^{\mathsf T}$，结果是什么形状？每一行代表什么？
4. 为什么 softmax 沿最后一维，而不是 head 维度？
5. 使用同形状 V，$AV$ 的输出与合并头后的形状是什么？
6. 若 query 只有 1 个位置，缓存共有 20 个位置，分数形状是什么？
