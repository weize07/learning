# Softmax 与 LLM 训练损失

- 学习日期：2026-10-08。
- 每日概览：[topics_by_date](topics_by_date.md)。
- 学习索引：[工作能力提升与实践手册](../index-2026-10-08.md)。

区分注意力权重与词表概率，理解 softmax、交叉熵及不同训练阶段的目标。

## 1. 为什么注意力权重与预测概率都常用 softmax？

两者都有同一个需求：**把任意实数分数变成非负、总和为 1，并能通过梯度学习的分配结果。** 但 softmax 是常见且有效的选择，不是数学上唯一可用的函数。

设有 $N$ 个候选项，分数为 $z_1,\ldots,z_N$：

$$
p_i=\operatorname{softmax}(z)_i
=\frac{e^{z_i}}{\sum_{j=1}^{N}e^{z_j}}
$$

可以分成两步理解：

1. 指数函数把任意实数分数变成正数，并保持大小顺序。
2. 除以所有指数值的总和，使结果总和为 1。

例如：

$$
z=[2,\,1,\,0]
$$

$$
e^z=[e^2,\,e^1,\,e^0]
\approx[7.389,\,2.718,\,1]
$$

$$
\operatorname{softmax}(z)
\approx[0.6652,\,0.2447,\,0.0900]
$$

最高分得到最多的份额，但其他候选项仍保留份额。有限 logits 下 softmax 的结果严格为正；mask 使用 $-\infty$ 可以将对应份额变为零，实际浮点计算也可能发生下溢。

**为什么不直接除以分数总和？**

模型产生的分数可能为负，甚至总和为零：

$$
z=[1,\,-1],\qquad \sum_i z_i=0
$$

直接归一化无法处理这个例子，也无法一般性地保证非负。softmax 不要求输入分数非负，且对所有分数同时加同一个常数不敏感：

$$
\operatorname{softmax}(z+c\mathbf{1})
=\operatorname{softmax}(z)
$$

因此真正影响分配的是分数之间的差异，而不是共同的基线。

**为什么使用指数函数？**

指数函数提供了一种平滑、单调、始终为正的映射。它还有一个清楚的相对偏好关系：

$$
\frac{p_i}{p_j}=e^{z_i-z_j}
$$

两个候选的分数相差 1，它们的份额比就是 $e:1$；分数差越大，偏好越明显。但过大的差异也可能使分布过度尖锐，这与 Attention 中的分数缩放有关。

**在 Attention 中，它有什么用？**

对每个 query，softmax 沿可访问的 key 位置分配权重，再汇总 value：

$$
o=\sum_j a_jv_j,\qquad a_j\ge0,\qquad \sum_j a_j=1
$$

这样，在 softmax 后、未施加 attention dropout 等后续操作时，输出是 value 向量的凸组合，而不是把任意正负分数直接当作系数。softmax 给模型提供平滑的“软选择”，而不是只能硬选一个位置。

注意力权重是一种信息汇总分配，不等于“这个位置是正确答案的概率”，也不自动构成可解释的因果关系。

**在输出端，它有什么用？**

next-token 预测需要在词表中形成一个类别分布，才能计算目标 token 的负对数似然或按分布采样。若真实目标类别为 $y$：

$$
\mathcal{L}=-\log p_y
=-z_y+\log\left(\sum_j e^{z_j}\right)
$$

softmax 与交叉熵组合后，对 logit 的梯度为：

$$
\frac{\partial\mathcal{L}}{\partial z_i}
=p_i-\mathbf{1}[i=y]
$$

其中 $\mathbf{1}[i=y]$ 在 $i=y$ 时为 1，否则为 0。这个梯度会推动目标 token 的 logit 上升、非目标 token 的 logit 下降。实际训练通常直接调用接收 logits 的交叉熵实现，用稳定的 log-sum-exp 计算，而不是先显式 softmax，再取 log。

数学上是一个概率分布，不代表它一定经过良好校准。例如模型给出的 90% 概率，不保证该类预测在实际数据上恰好有 90% 的正确率。

**为什么不直接选最大分数？**

argmax 可以在推理时用来选 token；但它是硬选择，其索引对 logits 的变化不提供通常所需的可微训练信号。softmax 则是平滑的分配函数，便于端到端训练。

softmax 本身的导数为：

$$
\frac{\partial p_i}{\partial z_j}
=p_i\left(\mathbf{1}[i=j]-p_j\right)
$$

它仍可能在分布极尖锐时出现小梯度，不能简单理解成“用了 softmax 就不会梯度消失”。上面的 softmax 加交叉熵的梯度，是二者组合后的结果。

**温度有什么作用？**

$$
p_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)},
\qquad T>0
$$

- 温度较低：分布更尖锐，更偏向最高分候选。
- 温度较高：分布更平缓。

Attention 中除以 $\sqrt{d_k}$ 同样具有调节分数尺度的作用，但其主要动机是补偿点积尺度随维度的增长，不应与生成时主动设置 temperature 完全混为一谈。

一句话总结：

> **Softmax 把实数分数变成平滑、归一化的竞争分配：在 Attention 中分配读取权重，在 LM Head 后分配下一个 token 的概率。它不是唯一方案，也不保证校准或永不出现小梯度。**

## 2. 除了交叉熵，还有哪些损失？Decoder-only LLM 一般用哪个？

**损失函数取决于训练任务，不单由网络架构决定。** 标准自回归 Decoder-only LLM 的预训练，以及常规监督微调（SFT），主要使用逐 token 的交叉熵，也就是正确目标 token 的负对数似然（NLL）。偏好优化、强化学习、蒸馏等阶段可以采用不同或组合的目标。

**先认识常见损失，不需要现在背下全部公式：**

| 损失 / 目标 | 主要衡量什么 | 常见用途 |
|---|---|---|
| 均方误差 MSE / L2 | 连续预测值与真实值的平方差 | 回归、价值网络训练、部分表示蒸馏 |
| 平均绝对误差 MAE / L1 | 连续预测值与真实值的绝对差 | 回归，相比平方误差较少放大大残差 |
| Huber | 小残差用平方形式，大残差用线性形式 | 兼顾平滑性与对大残差的鲁棒性 |
| 多分类交叉熵 | 给真实类别的概率是否足够高 | 单标签分类、next-token 预测 |
| 二元交叉熵 BCE | 二元事件的预测概率 | 二分类、多标签分类、部分成对偏好训练 |
| KL 散度 | 两个概率分布的差异 | 蒸馏、限制策略偏离参考模型 |
| 对比损失，如 InfoNCE | 正例相对于负例是否更相似 | embedding、检索、表示学习 |
| 排序损失，如 pairwise logistic / hinge | 偏好项是否比非偏好项得分高 | 排序、奖励模型、偏好学习 |

这些名称不一定互斥：InfoNCE 可以写成交叉熵形式；成对 logistic 排序可以写成二元交叉熵形式；对固定目标分布，最小化交叉熵等价于最小化相应方向的 KL 散度，因为二者只差目标分布的熵。

**为什么 next-token 预测通常不用 MSE？**

token 是离散类别，ID 通常只是词表索引，没有自然的数值距离。例如 ID 为 100 和 101 的词不一定更相似，ID 为 100 和 10000 的词也不一定更不相似。

因此不应把预测 token ID 与真实 ID 相减，再用平方误差训练。模型要学习的是“真实 token 在所有词表候选中有多大概率”，交叉熵更自然。也可以在概率向量上定义平方误差等其他目标，但这不是标准 next-token 训练的主流做法。

**预训练的交叉熵具体怎么计算？**

设序列为 $t_1,\ldots,t_n$。以下为简化示意，不计首 token / BOS 的处理差异，也忽略 padding：

$$
\mathcal{L}_{\text{CLM}}
=-\frac{1}{n-1}\sum_{i=1}^{n-1}
\log P_\theta(t_{i+1}\mid t_1,\ldots,t_i)
$$

即每个位置根据已有前缀预测下一个 token，取正确 token 概率的负对数，再对参与训练的位置取平均。

例如真实下一个 token 是“学习”，模型给它的概率越高，该位置的损失越小。使用自然对数：

| 给“学习”的概率 | 单位置损失 $-\ln p$ |
|---|---|
| $0.8$ | 约 $0.223$ |
| $0.2$ | 约 $1.609$ |
| $0.01$ | 约 $4.605$ |

这里“交叉熵”和“NLL”不是两个不同阶段：对 one-hot 的真实 token 标签，交叉熵就是正确类别的负对数似然。

**SFT 还用交叉熵吗？**

通常是。变化更多在数据与损失计算范围：

```text
用户问题 / prompt：作为条件
助手回答 / completion：作为需要学会生成的目标
```

常见配置只对 completion 或 assistant 的目标 token 计算损失，prompt 等位置不计入损失；也有全序列计算的配置，取决于数据格式和训练设置。

注意：**损失掩码与 causal mask 不同。** 前者决定哪些预测位置参加评分，后者决定注意力能读取哪些输入位置。prompt 可以不参与损失，但仍然是回答必须读取的上下文。

**偏好优化与强化学习阶段呢？**

| 阶段 | 常见训练目标 | 直觉 |
|---|---|---|
| 预训练 | Next-token 交叉熵 / NLL | 学习文本的条件分布 |
| SFT | 目标回答 token 的交叉熵 / NLL | 学习示范回答 |
| 奖励模型训练 | 成对偏好损失等 | 让更好的回答得分更高 |
| DPO 等偏好优化 | 基于回答对数概率、常涉及参考模型的偏好目标 | 学会偏好更好的回答 |
| PPO / GRPO 等强化学习 | 基于奖励 / 优势的策略目标，具体变体可带裁剪、KL 等项 | 提高生成高奖励回答的倾向 |
| 蒸馏 | 可用教师软分布的交叉熵 / KL，也可对教师生成文本做 SFT | 学习教师的输出分布或示范 |

这些阶段不一定全部使用，也不一定按表中顺序串行执行。不能把现代 LLM 的全部训练概括为“始终只用交叉熵”，也不能因为有 PPO / GRPO，就认为预训练不再做 next-token 预测。

普通使用时的推理不依靠损失函数选择下一个 token，而是用输出 logits / 概率与解码策略；评测有参考答案时可以额外计算 NLL，但通常不更新参数。

另外，Attention 内的 softmax 通常没有一个独立的“注意力交叉熵监督标签”。最终 token 损失通过反向传播更新 Attention 等模块；辅助监督是另一种可选设计。

> **标准 Decoder-only LLM 的预训练和常规 SFT 主要用逐 token 交叉熵；偏好、强化学习和蒸馏阶段按任务使用其他或组合目标。架构告诉你“怎么计算”，损失告诉你“朝什么目标学习”。**
