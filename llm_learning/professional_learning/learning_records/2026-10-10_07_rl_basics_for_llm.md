## 1. 先看一个完整例子

给定问题与资料：

```text
问题：申请一定在三个工作日内完成吗？
资料：[D1] 申请通常需要三个工作日处理。
```

模型可能生成：

- 回答 A：“通常需要三个工作日，但资料没有保证一定完成。[D1]”
- 回答 B：“一定在三个工作日内完成。[D1]”

为了演示，假设我们已经有一个可靠的评分规则，给 A 奖励 +1，给 B 奖励 -1。数字是教学设置，不是标准 reward 范围。

强化学习希望做到：

> 模型根据自己生成的回答获得反馈，再调整参数，让以后更容易生成高奖励回答。

与 SFT 的区别：

| SFT | 本例中的强化学习 |
|---|---|
| 给模型一份示范答案 | 让模型先生成，再评价结果 |
| 学习示范的下一个 token | 根据奖励调整动作选择的概率 |
| 示范前缀通常由真实标签提供 | rollout 的回答前缀来自策略自己的选择 |

这不意味着强化学习不需要人工数据：评分规则或奖励模型本身也可能依赖标注。

## 2. 策略：不是额外模型，而是生成模型的选择规则

“策略”表示在当前条件下如何选择动作。在 LLM 中，就是我们已经学过的词表概率：

```text
问题 + 资料 + 已生成前缀
           ↓
Transformer → LM Head → 概率分布
           ↓
选择下一个 token
```

例如候选 token 的示意概率为：

| 下一 token | 概率 |
|---|---:|
| “通常”对应的 token | 0.6 |
| “一定”对应的 token | 0.3 |
| 其他 token 合计 | 0.1 |

实际 tokenizer 未必将这两个词各切为单个 token，这里只为直觉说明。

调整策略，就是改变模型参数，从而改变类似的概率分布。不是硬编码“以后永远选通常”；其他问题可能确实需要确定回答。

## 3. 状态、动作、状态转移

| 术语 | 本例中的含义 |
|---|---|
| 状态 | 问题、资料、已生成的回答前缀 |
| 动作 | 选择一个下一 token |
| 状态转移 | 把选出的 token 追加到回答前缀 |
| 终止 | 输出结束 token，或达到规定终止条件 |

```text
状态 0：问题 + 资料，回答尚为空
   ↓ 动作：选一个 token
状态 1：问题 + 资料 + 第一个回答 token
   ↓ 动作：再选一个 token
状态 2：问题 + 资料 + 前两个回答 token
   ↓
……直到结束
```

这里的“状态”是整个可用条件，不是只指单个 token 的隐藏向量，也不是模型参数。普通文本生成的转移主要是追加 token；工具 Agent 还可能收到外部执行结果，状态更复杂，后面再学。

## 4. Rollout：把一次尝试记录下来

Rollout 可以理解为“按当前策略跑一次生成过程”：

```text
从问题开始
→ 选 token 1
→ 选 token 2
→ ……
→ 回答结束
→ 获得评分
```

训练时通常收集一批这样的尝试，保存动作、采样时的概率以及奖励等信息，再用于更新。

“在线采样”在这里不是必须联网或直接面对真实用户，而是训练过程中用当前策略采集新回答。

## 5. 奖励与回报：得分可以晚于动作

奖励是反馈，不是梯度，也不必每生成一个 token 都有一个新的质量评分。

例如实际质量只在回答结束时评价：

```text
前面各 token：即时奖励 0
回答结束：最终奖励 +1 或 -1
```

“回报”是从某一步往后累积的奖励。在最简单的无折扣、只有结束奖励的例子里，前面各步的回报都包含最终这个评分。

这意味着前面动作会受到最终结果的训练信号，**但不是证明每个 token 都同样有功或有错**。到底哪个选择导致了好结果，叫信用分配问题，是强化学习的难点。

假设平均每次回答的奖励是 -0.2，训练后提高到 +0.5，表示策略在这个评分体系下改善；如果评分体系有漏洞，不一定意味着真实质量改善。

## 6. 为什么还需要“预期”和“优势”？

先固定同一个问题、资料与已生成前缀，也就是同一个状态。模型接下来可以选择不同 token，随后产生不同回答：

```text
相同问题、资料与回答前缀
    ├→ 选择 token A → 继续生成 → 最终回报 0.9
    ├→ 选择 token B → 继续生成 → 最终回报 0.5
    └→ 选择 token C → 继续生成 → 最终回报 0.2
```

这里是三次可能的尝试，不是同一次生成同时走三条路线。

**Critic 预测：从这个状态出发，按当前所评估的策略继续生成，平均能获得多少回报？** 这个状态价值记为 $V(s)$，不是提前知道本次会得几分。

假设 Critic 估计预期回报为 0.6：

| 本次实际回报 | 同一状态的预期回报 | 优势估计 | 直觉 |
|---:|---:|---:|---|
| 0.9 | 0.6 | +0.3 | 比通常表现好 |
| 0.5 | 0.6 | -0.1 | 比通常表现差 |
| 0.2 | 0.6 | -0.4 | 明显比通常表现差 |

预期 0.6 是假设的 Critic 输出，不是表中三个数的简单平均。真正的期望需要考虑各动作的选择概率，以及之后继续生成的各种可能；每个完整回答也只是一次采样。

入门时用：

$$
\widehat A_t=G_t-V(s_t)
$$

$G_t$ 为实际采样回报，$V(s_t)$ 为预期回报。它是优势的一种估计，不是真实优势函数的精确值；PPO 常使用 GAE 等更复杂估计，暂不展开。

**Critic 的预期从哪里来？** 它也需要训练：输入生成前缀，预测回报，用 rollout 得到的回报目标来调整预测。不是人工为每个问题规定一个难度分数；估计也可能有误。

用一句话区分：

- **Reward**：这次得到什么反馈。
- **Return / 回报**：从这一步往后的反馈累计。
- **Critic / 价值**：在这个状态下，通常预期得到多少回报。
- **Advantage / 优势**：这次相对于预期好多少或差多少。

为什么减预期？一个重要作用是降低策略梯度估计的方差。在通常的策略梯度条件下，减去不依赖当前动作的状态基线，不改变期望梯度；不是为了把高分回答改判为错误。基线不一定每次都降低方差，需合理估计。

注意：优势为负不等于答案绝对错误；单次正优势也不能证明所选 token 是好结果的唯一原因。要通过许多采样学习，这仍涉及信用分配问题。

### 6.1 Critic 的训练数据从哪里来？

通常由训练策略的 rollout 自动构造：先生成回答，取得奖励，再为轨迹中的各个前缀构造回报目标。不需要人工逐一标注“这个前缀的期望为 0.6”。

```text
策略生成回答，记录各步前缀
              ↓
RM / 规则 / 环境提供奖励
              ↓
计算每一步的回报目标
              ↓
训练样本：（前缀状态 s_t，回报目标 G_t）
              ↓
Critic 预测 Vψ(s_t)，用回归损失拟合目标
```

最简单的完整终止轨迹：前面奖励全为零、结束奖励为 0.9，不使用折扣或其他惩罚。则该轨迹中每个尚未结束的前缀，其采样回报目标都为 0.9：

| Critic 输入 | 本条轨迹的回报目标 |
|---|---:|
| 问题 + 资料，回答未开始 | 0.9 |
| 问题 + 资料 + 第一个回答 token | 0.9 |
| 问题 + 资料 + 前两个回答 token | 0.9 |

目标相同不意味着所有状态价值相同。一条轨迹的回报只是一次随机结果；Critic 结合不同轨迹与相似状态的经验，学习预期，而不是把每个前缀永远记为这次分数。

一种简单价值损失是 MSE：

$$
\mathcal L_V=\frac1N\sum_t\left(V_\psi(s_t)-G_t\right)^2
$$

回报目标在这项回归损失中作为固定目标。实际 PPO 可能使用折扣、逐 token 的 KL 奖励惩罚、截断时的价值 bootstrap、GAE 构造的回报目标与价值裁剪，因此不一定把最终 RM 分数直接复制给每个位置。

Reward Model 的偏好标签也不一定全来自人工，可以来自模型或其他可信标注流程；不过 Critic 的价值目标通常来自 rollout 的奖励与回报估计，二者的数据构造目的不同。

### 6.2 Critic 是什么架构？

LLM PPO 中一种常见设计是：因果 Transformer 骨干 + 标量价值头。每个前缀末尾位置的隐藏向量用于预测这个状态的价值：

$$
V_\psi(s_t)=h_t w_V+b_V,\qquad
h_t\in\mathbb R^{1\times d_{\text{model}}},
\quad w_V\in\mathbb R^{d_{\text{model}}\times1}
$$

这里的 $w_V$ 是价值头的权重，不是 Attention 的 value 投影 $W_V$。名称相似，职责不同。

```text
问题 + 资料 + 回答前缀
             ↓
因果 Transformer
             ↓
前缀末尾隐藏向量：d_model 维
             ↓
价值头：d_model → 1
             ↓
预计回报，一个实数
```

对完整轨迹批量计算时，隐藏状态可为 `[B,n,d_model]`，价值头输出 `[B,n,1]`，再选择与各状态 / 动作正确对齐的位置。评估选择下一 token 前的状态，不得让价值预测读取该状态之后的未来内容。

骨干可与策略共享，也可用独立模型；初始化方式与模型规模依实现而定，不必与 RM 相同。共享时同时处理策略损失和价值损失，梯度会共同影响共享参数，不能声称完全互不影响。

| 模型角色 | 常见输入 / 输出 | 学习目标 |
|---|---|---|
| 策略 / Actor | 前缀 → 下一 token 概率 | 学习动作选择 |
| Reward Model | 条件 + 完整回答 → 质量分数 | 学习评价 |
| Critic | 前缀 → 预期回报标量 | 用轨迹回报拟合预测 |

在常见 RM-PPO 循环中，RM 通常固定，策略与 Critic 持续更新；这不是说所有算法都必须使用独立 Critic，GRPO 等方法会采用不同优势估计。

## 7. 有了反馈，怎么更新？采样不能求导怎么办？

沿用上一节的同一状态。假设采样时模型给出的概率为：

| 下一 token | 概率 |
|---|---:|
| A | 0.4 |
| B | 0.3 |
| 其他合计 | 0.3 |

本次抽到 A，随后生成完整回答，回报为 0.9，Critic 原先估计为 0.6，因此这一步的简单优势估计为 +0.3。

训练意图是：**让类似条件下选择 A 更容易发生。** 调整的是模型参数，不是已经生成的文字，也不是修改 token A 的 ID。

### 7.1 先联系 SFT：你已经见过提高 token 概率

SFT 中，假设示范的目标 token 是 A，会最小化：

$$
\mathcal L_{\text{SFT}}=-\log P_\theta(A\mid s)
$$

强化学习里，A 不是预先指定的标准 token，而是策略这次实际选中的动作。通过结果判断应强化还是抑制它，用优势加权：

$$
\mathcal L_{\text{illustration}}
=-\widehat A\,\log\pi_\theta(a\mid s)
$$

这里 $\pi_\theta$ 就是生成模型的 token 概率，$a$ 是固定记录下来的已选 token。

- $\widehat A=+0.3$：该项推动提高 A 的概率。
- $\widehat A<0$：该项反过来推动降低已选动作的概率。

在策略更新这项损失时，把优势作为固定估计量，不让策略损失通过优势去修改评分器或 Critic。Critic 用自己的价值训练目标更新。

### 7.2 为什么离散 token 也能参与梯度训练？

要区分两条路径：

```text
不能直接这样求导：
采样结果“选中了 A” → 对这个离散选择求普通导数

实际用的路径：
模型参数 → logits → softmax → A 的概率 → log 概率 → 损失
```

**固定本次选中的 A，取出模型赋给 A 的概率。这个概率由参数连续计算而来，可以求导。** 不需要对“抽中了 A”这一随机事件本身求导，也不要求把 token ID 当成连续数值。

比如更新后 A 的概率从 0.4 变成 0.45，是这项正优势训练希望的方向；数字只是示意，共享参数、其他样本与约束会共同影响真实更新。

### 7.3 把第 6、7 节串起来

```text
记录状态 s 与采样动作 A
          ↓
继续生成回答 → 得到回报 0.9
          ↓
Critic 对原状态预计 0.6
          ↓
优势估计 = 0.9 - 0.6 = +0.3
          ↓
构造 -0.3 × log Pθ(A | s)
          ↓
对模型参数求导并更新
```

完整回答的其他生成位置也有各自的状态、已选动作与优势估计。这里只看一个位置，避免把所有步骤混在一起。

**这只是策略梯度的入门示意，不是完整 PPO。** 它说明如何通过采样反馈学习概率；PPO 还需要处理新旧策略的概率比与受限更新。优势信号也不保证每个被强化动作都因果上正确，最终仍需实际生成评测。

## 8. 现在才引出 PPO

如果根据这批回答反复大幅更新，策略可能变化过快，过拟合这批反馈或利用奖励漏洞。

PPO 的核心动机之一是：

> 根据优势学习，同时避免在同一批采样数据上沿有利方向过度更新。

因此它要比较采样时的旧概率与更新后的新概率，并用 clip 修改目标。**先理解状态、动作、回报和优势，再回到 PPO 的概率比与裁剪公式。**

参考模型约束是 LLM 后训练中常见的另一个设计，用来减少偏离参考行为；它与 Critic、采样旧策略都不是同一角色。

## 9. 阅读进度与资料

当前只需能用自己的话区分：

- 策略：选择下一 token 的概率规则。
- 状态：问题、资料与已生成前缀。
- 动作：下一 token 的选择。
- 奖励：反馈；回报：后续反馈的累计。
- 价值：预期回报；优势：相对于预期的表现。
