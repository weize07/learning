## 1. 先纠正最常见的流程图

只写“Base → SFT → RL → SFT → RL”会隐藏一条关键关系：**第二阶段 RL checkpoint 用来生产第三阶段的数据；第三阶段原文写的是微调 DeepSeek-V3-Base。**

```text
DeepSeek-V3-Base
  ├─ 权重 → ① 数千条冷启动 SFT
  │            └─ 权重 → ② 推理导向 RL
  │                          └─ 生成与筛选 → 约 600k 推理样本 ─┐
  │                                                         │
  │          V3 数据管线 / 部分既有 SFT 数据 → 约 200k 通用样本 ┤
  │                                                         ↓
  └─ 权重 ─────────────────────────────→ ③ 约 800k 数据 SFT
                                                            │
                                                       两个 epoch
                                                            ↓
                                                   ④ 全场景 RL
                                                            ↓
                                                       DeepSeek-R1
```

上图的阶段编号对应论文四阶段。R1-Zero 的部分输出可作为冷启动数据来源，但论文没有说“把最终 Zero 权重直接当作 R1 第一阶段权重”。

“重新从 Base 出发”描述的是参数初始化；不代表丢掉前阶段的知识收益。前阶段通过生成并筛选的数据，把行为传给下一轮模型。

## 2. 阶段一：冷启动 SFT

### 是什么、为什么

**论文事实**：收集数千条高质量长推理数据，微调 V3-Base，作为 RL 的起始 actor。

目标包括减少 Base 直接进入 RL 的初期不稳定，以及提高推理表达的可读性。

### 数据怎样得到

作者描述的途径包括：

- 用长推理示例做 few-shot prompting。
- 提示模型给出详细解答，并包含反思与验证。
- 收集可读的 R1-Zero 输出。
- 通过人工标注者后处理改善数据。

这不是“全部由人从零写几千份解题过程”，也不是“完全无人处理”。

### 学到什么、代价是什么

**机制解释**：SFT 把一部分概率质量放到较合适的回答形式与策略上，使后续探索不必从任意表达开始。

它也会引入人类选择的模式与偏好。数据过窄、错误推导或过长模板，都可能带来局限。论文没有充分披露每种来源的数量和完整模板集合，不能自行补比例。

## 3. 阶段二：推理导向 RL

### 是什么

**论文事实**：在冷启动模型上进行类似 R1-Zero 的大规模 RL，面向数学、代码、科学与逻辑推理中答案较明确的任务。

仍要区分：

- 问题 domain：数学 / 代码 / 科学 / 逻辑。
- 奖励类型：正确性、语言一致性。
- 优化算法：GRPO。

domain 不是 loss 名称，奖励也不是算法本身。

### 为什么加入语言一致性

作者观察到多语言提示下的 CoT 语言混杂，加入按推理中目标语言词占比计算的一致性奖励。

**作者报告**：正确性奖励与语言一致性奖励直接相加；语言对齐使可读性更符合偏好，但消融中推理表现略有下降。报告未在这里给出可用于精确重建的完整量化结果。

这是一项重要取舍：**用户体验与某个推理分数并不总是同方向。**

不能进一步想当然地写出所有任务的分词、语言识别器、奖励归一化或权重细节。简单地说“直接相加”，也不消除不同奖励数值尺度的影响。

## 4. 阶段三前半：把探索结果变成数据

### 4.1 约 600k 推理数据

作者对推理 RL checkpoint 进行多次采样，保留正确回答，并扩展可覆盖的数据类型。

其中部分数据不再只靠规则判断：把真实答案与模型预测交给 DeepSeek-V3，作生成式评判。还过滤语言混杂、不利于阅读的长段落和代码块形式的推理。

这里的过滤描述不能扩大成“所有编程答案都删除代码”。原文讨论的是推理轨迹可读性，任务仍包括代码。

**为什么多采样**：同一问题可能有成功和失败轨迹，筛选能提取较好的示范。

**为什么仍有风险**：最终答案正确不保证推导逐步正确；生成式裁判也可能误判。正确性、可读性和轨迹可靠性是不同门槛。

### 4.2 约 200k 非推理数据

作者沿用 V3 的数据管线，并复用部分 V3 SFT 数据。覆盖写作、事实问答、自我认知、翻译。

部分任务用 V3 生成潜在推理过程；简单问候不强行加入 CoT。

因此这 800k 数据不能简单理解为“最终 R1 对 800k 道数学题各生成一次”。它是多阶段、多来源、经过选择的训练集合。

### 4.3 筛选本身会改变 domain 分布

下面是**分析公式**，不是官方配比：

$$
N_d^{\mathrm{retained}}
\approx N_d^{\mathrm{prompts}}
\times G_d
\times a_d.
$$

$a_d$ 是该域候选回答的保留率。公式忽略去重、每题配额与样本相关性，只用于理解数量关系。

例如两个域各生成 1,000 个候选，一个保留 80%，另一个保留 20%，最终得到 800 与 200 条。原始 1:1 的候选预算会变成 4:1 的保留样本。

所以配方管理不能只看采样前的题数，还要看保留率、每题重复、有效 token 与能力覆盖。

## 5. 阶段三后半：为什么又回到 SFT？

**论文事实**：用约 800k 样本，在 V3-Base 上微调两个 epoch。

**机制解释**：

- RL 用奖励搜索较好行为。
- 拒绝采样把成功行为筛成示范。
- SFT 可以把这些示范与通用任务共同吸收，重新得到一个更均衡的起点。

这不是给 RL 输出做“离线美化”，而是实际更新模型参数。

如果只把通用数据看成“为了聊天顺一点”，会低估它的作用：写作、事实回答、翻译与无需长推理的任务，本身就是独立能力目标。

两个 epoch 是数据遍历口径，不等于模型得到两倍独立知识。600k / 200k 是样本数口径，约 75% / 25% **不能直接读成 token、梯度或算力占比**。

## 6. 阶段四：全场景 RL

**论文事实**：混合不同问题分布与奖励信号，继续提升推理，同时对齐 helpfulness 与 harmlessness。

| 数据 / 目标 | 作者描述的信号 | 评分范围 |
|---|---|---|
| 数学、代码、逻辑推理 | 规则式奖励 | 与任务正确性相关的结果 |
| 一般复杂场景 | 奖励模型捕捉人类偏好 | 按对应目标设计 |
| Helpfulness | 实用性、相关性 | 最终摘要 / 回答，而非整段推理 |
| Harmlessness | 风险内容检查 | 整个回答，包括推理与摘要 |

这解释了为什么“R1 不用 RM”是不准确的：那是对 Zero 某个方案的描述，不是整个 R1 家族的统一规则。

这里的 RL 也不应未经证据替换成 DPO。算法需要看实际目标与采样方式，不是看到“偏好”二字就归类为 DPO。

## 7. 各域在哪一阶段增强？

| 能力域 | 主要训练接点 | 不能保证什么 |
|---|---|---|
| 数学 / 逻辑 | Base 基础、冷启动、推理 RL、精选示范、最终 RL | 每条推理过程都正确 |
| 代码 | Base 代码知识、验证反馈、精选轨迹与后续 RL | 算法题提升自动转成大型仓库工程能力 |
| 科学知识推理 | Base 知识与推理任务奖励 | 开放世界事实永远可规则验证 |
| 写作 / 事实问答 / 翻译 | 通用 SFT 数据与全场景 RL | 所有语言、所有事实都同等提升 |
| 表达与可读性 | 冷启动、过滤、语言奖励 | 更易读一定带来更高正确率 |
| 安全与用户偏好 | 通用数据与最终奖励 | 误拒、偏差和越权风险被完全消除 |

论文没有公开完整的各 domain 配比表，也没有给出每一阶段对每种能力的独立贡献百分比。不要用推测数字填满矩阵。
