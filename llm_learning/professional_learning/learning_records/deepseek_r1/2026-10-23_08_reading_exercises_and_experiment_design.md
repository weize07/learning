## 2. 不用 GPU 的四道手算

### 题 A：一对三的组内优势

同题奖励为 `[1,0,0,0]`，用总体标准差，无稳定项。求均值、标准差和四个优势。

**核对答案**：

$$
\bar r=\frac14,\qquad
\sigma=\frac{\sqrt3}{4},\qquad
A=\left[\sqrt3,-\frac1{\sqrt3},-\frac1{\sqrt3},-\frac1{\sqrt3}\right].
$$

应能解释：成功少不等于成功样本自动出现；若采样全错，这种对比信号就不存在。

### 题 B：裁剪方向

$A=-1,\rho=1.3,\epsilon=0.2$。min 项是 -1.2 还是 -1.3？

**核对答案**：-1.3。差回答的概率反而变高时，目标不把这项惩罚截成 -1.2。参见[完整算例](2026-10-23_03_grpo_objective_and_walkthrough.md)。

### 题 C：评测与选择

8 个回答有 3 个正确，错误答案中同一个错误值出现 4 次。计算 pass@1、pass@2 估计，并判断频次投票能否选对。

**核对答案**：37.5%、约 64.29%；投票选错。正确候选存在，不等于无真值的选择器能识别它。

### 题 D：样本占比不是 token 占比

**教学假设**：600k 推理样本平均 2,000 token，200k 通用样本平均 200 token，不考虑 prompt、padding 与截断。

**核对答案**：

- 推理：1.2B token。
- 通用：40M token。
- 推理样本占 75%，但在本例回答 token 中约占 96.77%。

这不是 R1 实际长度或 token 配比。例子只解释为什么不能从 600k / 200k 直接推出计算分配。

## 3. 六个容易答错的概念题

| 问题 | 合格回答应包括 |
|---|---|
| Zero 是否不需要数据？ | 仍需预训练基础、问题池、验证信息与规则；只是无前置 SFT |
| GRPO 为什么不训练 Critic？ | 用同题奖励作基线；不是取消 actor、reward 或所有辅助计算 |
| 最终 R1 是否从 Zero 权重一路训练？ | 不应这样概括；区分冷启动数据来源与第三阶段重新从 Base 做 SFT |
| 反思文字能证明推理忠实吗？ | 只能先视为行为证据，需要干预与独立过程验证 |
| 64 次采样估计 pass@1 是否就是 pass@64？ | 否；单次成功概率估计与至少一次成功是不同指标 |
| R1 数学强，能否直接替换业务 Agent？ | 还需工具、格式、多轮、环境、权限、预算和任务验收 |

回答时应能指向原文章节或公式，而不是只说“论文证明了”。

## 4. 一个可选的小规模研究问题

**问题**：在固定学生模型与任务划分下，精选的推理解题文本，是否比只保留最终答案更有帮助？

这是蒸馏数据形式实验，不是完整 R1 复现。是否下载模型、安装训练环境、花费 GPU 或使用外部 API，需要另行决定；本次不执行。

### 4.1 先定义任务与数据

- 选择自拟、可合法使用且可确定验证的算术或小程序任务。
- 按模板族 / 题型拆分训练与测试，避免只改数值的近重复跨集合。
- 教师候选保留来源、采样配置、验证和过滤结果。
- 答案 / 隐藏测试只进入验证器，不泄露到未声明的模型上下文。
- 代码执行必须使用适当隔离与资源限制。

### 4.2 对照组

| 组别 | 条件 | 作用 |
|---|---|---|
| B0 | 原始学生，不微调 | 测初始化能力 |
| B1 | 相同题目的最终答案 SFT | 看答案监督效果 |
| B2 | 相同题目的精选完整轨迹 SFT | 看轨迹提供的增量 |
| B3，可选 | 保持题目与长度接近、但只含无效重复的材料 | 研究长度与有效内容的区别；不能混入正式训练产物 |

B3 不是必须项，也不应被当成产品数据建议。先完成 B0–B2 的可信比较。

### 4.3 哪些变量需要控制？

固定学生 checkpoint、数据划分、任务集合、提示与评分器。记录训练 token、更新次数、学习率、随机种子和实际长度。

**不能同时假装所有预算都相同**：B1 与 B2 的回答长度不同，相同样本数不等于相同 token 预算。应明确采用“相同题目比较”还是“相同计算预算比较”，必要时分别做两种实验。

### 4.4 至少报告哪些结果？

| 维度 | 记录 |
|---|---|
| 任务收益 | 分题型 pass@1、未见模板表现 |
| 生成成本 | token 分布、延迟、截断和重复 |
| 可靠性 | 格式失败、错误推理但答案正确、解释与答案不一致 |
| 稳定性 | 多随机种子或重复评测波动 |
| 数据成本 | 候选数、保留率、教师生成与验证成本 |

只要 B2 分数更高还不够。还要排除测试泄漏、更多训练 token、模板匹配或评测提示差异的解释。

## 5. 如果之后想验证 GRPO，再增加什么？

先完成最小数据与奖励验证，再引入采样训练。

需要明确的不是“安装哪个库”，而是：

- 每题 $G$ 与不同问题 batch 数。
- 奖励分解与零方差处理。
- old 同步、ref 固定 / 刷新规则。
- token mask、长度归约、截断与无效回答。
- clip、KL 的实现位置与版本。
- rollout 成本、验证耗时、独立评测和停止条件。

初期指标应包括：全对 / 全错组占比、奖励与外部准确率的相关性、KL、长度、重复、截断、各域覆盖。

若训练奖励提高、独立正确率不升，优先检查验证器、数据泄漏、长度与采样口径，不先宣称“出现了推理能力”。

## 6. 怎样记录完成状态？

| 状态 | 能写什么 |
|---|---|
| 材料已提供 | 有讲义、链接和练习，未代表阅读 |
| 阅读与手算完成 | 能解释阶段和公式；记录实际问题与答案 |
| 设计评审完成 | 数据、对照、预算和验收协议已明确 |
| 实验执行完成 | 有实际配置、日志、产物和结果 |
| 结论获得支持 | 通过独立评测与相应控制实验，注明适用范围 |

不能从第一行直接跳到最后一行。课程资料里写出的数字，只有明确注明“本地实测”且有证据时，才算个人实验结果。
