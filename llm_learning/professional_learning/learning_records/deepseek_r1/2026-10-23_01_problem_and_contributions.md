# 01 · R1 在回答什么问题：模型家族、贡献与边界

- 编写日期：2026-10-23；状态：待阅读，未复现实验。
- 导航：[专题入口](README.md) → [下一章：R1-Zero](2026-10-23_02_r1_zero_and_rewards.md)。
- 主要证据：[原论文 v1 §1–2](https://arxiv.org/html/2501.12948v1#S1)；[官方模型说明](https://github.com/deepseek-ai/DeepSeek-R1#3-model-downloads)。

## 1. 先把研究问题改写成可检验的问题

“让模型更聪明”太模糊。R1 的主线可拆成三问：

1. **探索**：从已有 Base 出发，不先提供推理解题示范，能否用结果奖励显著提高推理任务成绩？
2. **可用性**：直接 RL 产生的行为，怎样变得可读、稳定，并兼顾一般用户任务？
3. **迁移**：大模型获得的行为，能否通过数据传递给更小的模型？

对应的研究对象分别是 R1-Zero、R1 和 R1-Distill。不要把三个对象的条件合并成“R1 全程无 SFT”。

## 2. 先认清四种名字

| 对象 | 起点与作用 | 不能混淆的对象 |
|---|---|---|
| DeepSeek-V3-Base | 已预训练的基座，是 R1 / R1-Zero 的起点 | 表 4 中名为 DeepSeek-V3 的对照，不应自动读成裸 Base |
| DeepSeek-R1-Zero | V3-Base 上直接进行推理 RL，检验无前置 SFT 的路线 | 随机初始化模型；也不是最终 R1 的同义词 |
| DeepSeek-R1 | 用冷启动、推理 RL、数据筛选与 SFT、全场景 RL 构建的模型 | “Zero 再加一个漂亮输出模板” |
| DeepSeek-R1-Distill-* | 从指定 Qwen / Llama checkpoint 出发，用精选文本做 SFT | 从 R1 权重里裁出的小型 MoE |

官方说明列出 R1 / R1-Zero 为 MoE：总参数约 **671B**，每 token 激活约 **37B**。这不是“只需装下 37B 权重”的保证；激活计算量与全部权重存储是不同口径。

架构背景见 [MoE 基础课](../2026-10-09_06_moe_architecture.md)。本专题聚焦后训练，不展开 V3 的预训练与分布式实现。

## 3. “没有 SFT”究竟删掉了什么？

R1-Zero 删掉的是：**在这条 Base → 推理 RL 路线上，先用一套推理示范做监督微调的环节。**

它没有删掉：

- 预训练所得的语言、代码、数学基础。
- 训练问题池。
- 正确答案、测试条件或其他奖励所需的信息。
- 格式模板与人为设计的验证规则。
- 多次生成、奖励计算、反向传播和优化器更新。

因此“没有参考解题过程供模仿”不等于“没有监督信息”。数学答案可以只给验证器，不给模型；验证器再把结果压成奖励。

**机制解释**：预训练改变模型能较容易生成哪些行为，RL 改变这些行为在目标任务上的概率分布。论文的结果支持这个组合有效，不能证明预训练从未见过反思或推导模式。

## 4. 自回归生成没有消失，学习目标却变了

同一个模型仍按以下分解生成回答：

$$
\pi_\theta(y\mid x)=\prod_{t=1}^{T}
\pi_\theta(y_t\mid x,y_{<t}).
$$

但“如何生成”与“为什么调整参数”不是同一件事：

| 训练方式 | 回答从哪里来 | 主要更新信号 |
|---|---|---|
| 预训练 | 语料中的真实续文 | 提高真实 next token 的概率 |
| SFT | 人工或模型筛选出的示范 | 提高示范回答 token 的概率 |
| R1 的推理 RL | 当前采样策略自己的回答 | 奖励、相对优势、策略约束 |
| R1 学生蒸馏 | 精选教师文本 | 对教师文本做 SFT |

RL 更新时也会计算已采样 token 的概率，但这些 token 不必是“golden token”。低奖励回答可以被降低概率，而不是被当成正确标签模仿。

因此两个说法可以同时成立：

- R1 仍是自回归语言模型。
- R1 的 RL 阶段不是普通的“参考答案 next-token 交叉熵训练”。

## 5. 论文贡献不是发明所有零件

| 层次 | 本文做了什么 | 贡献边界 |
|---|---|---|
| 训练现象 | 报告直接 RL 的推理提升、长回答和反思行为 | 不是通用智能的定理 |
| 训练路线 | 把探索、可读性、数据再利用与对齐组合起来 | 阶段顺序与权重继承仍需仔细读 |
| 能力迁移 | 通过精选数据训练六种学生模型 | 不是所有小模型都能无损继承教师能力 |
| 开放产物 | 发布模型权重与说明 | 权重开放不等于训练数据、所有中间产物和完整配方开放 |
| 优化算法 | 使用 GRPO | GRPO 来自先前的 [DeepSeekMath](https://arxiv.org/abs/2402.03300)，不是 R1 首创 |

这篇论文最值得学习的是“怎样让目标、数据、算法、评测形成闭环”，而不是只记住一个算法缩写。

## 6. 看结果前先写下证据标准

以下三种结论需要不同证据：

- **性能结论**：“这个 checkpoint 在这个协议下分数更高。”需要固定任务、提示、采样与评分方法。
- **因果结论**：“提升主要来自这个组件。”需要尽量只改变该组件的消融。
- **机制结论**：“模型用某种内部机制获得能力。”仅靠输出文本和总分通常不足，需要额外干预与分析。

“Aha moment”是值得研究的行为样本，不会自动同时满足后三种证据要求。后续章节会反复用这个区分读论文。
