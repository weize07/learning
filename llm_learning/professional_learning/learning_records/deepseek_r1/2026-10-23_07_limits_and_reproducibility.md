# 07 · 局限与研究判断：失败尝试不等于方法被判死刑

- 编写日期：2026-10-23；状态：待阅读，未复现失败或成功结果。
- 导航：[上一章](2026-10-23_06_evaluation_and_evidence.md) · [专题入口](README.md) · [下一章：练习](2026-10-23_08_reading_exercises_and_experiment_design.md)。
- 主要证据：[v1 §4.1–4.2](https://arxiv.org/html/2501.12948v1#S4)、[§5](https://arxiv.org/html/2501.12948v1#S5)。

## 1. PRM：逐步打分为什么没有成为主路线？

PRM（Process Reward Model）尝试评价中间步骤，而不是只看最终结果。

**作者报告的困难**：

1. 通用推理里很难一致地定义“一个步骤”。
2. 中间步骤是否正确难以可靠标注；自动标注有误差，人工标注难规模化。
3. 长期优化学习型评分器会产生 reward hacking 风险；更新评分器增加成本与流程复杂度。

**机制解释**：更细粒度的信号只有在可信时才有价值。若中间评分偏向某种措辞或形式，策略可能优化评分器的偏好，而不是解题可靠性。

**不能推出**：PRM 永远无效。作者也指出 PRM 可帮助候选重排或引导搜索。用于训练奖励、用于推理选择、用于离线分析，是不同用途。

若要进一步验证，需在同一模型、任务与计算预算下比较结果奖励、过程奖励及组合，并检查评分器分布外误差。v1 的失败经验不是覆盖所有 PRM 的定理。

## 2. MCTS：为什么不能直接复制棋类成功经验？

MCTS 把生成拆成可搜索的节点，用价值估计决定探索方向。作者尝试用搜索得到的回答训练 actor 与 value model，再迭代。

**作者报告的困难**：

- 文本动作空间与分支规模大。
- 限制节点扩展数可以控制开销，却可能困在局部最优。
- 搜索质量依赖价值模型；细粒度价值模型本身难训练。

**机制解释**：棋局的状态、合法动作、终局规则比较明确；自然语言中的步骤切分、等价状态和价值判断更不稳定。

但“文本生成难搜索”不是“所有文本搜索都没意义”。推理时用已有价值模型改善选择，与从搜索数据持续自我提升，是不同命题。本文没有证明前者无效。

## 3. 四项作者主动披露的产品局限

| 局限 | 原文含义 | 对使用者的影响 |
|---|---|---|
| 通用能力 | function calling、多轮、复杂角色扮演、JSON 任务仍落后于 V3 | 推理榜单不能代替应用验收 |
| 语言混杂 | 主要优化中文与英文，其他语言可能出现混杂 | 必须按目标语言评估 |
| 提示敏感 | 作者观察 few-shot 会降低表现，建议直接说明问题与格式 | 不照搬其他模型的提示模板 |
| 软件工程 RL 不充分 | 执行评估耗时长，限制大规模 RL 应用 | 仓库工程增益小于部分数学 / 算法任务的增益 |

这些描述限定于论文对象与实验条件。不要把原版 R1 的建议永远套在后续版本或全部学生模型上。

## 4. 对“涌现”应保持什么证据标准？

| 观察 | 它支持什么 | 它还不能独立证明什么 |
|---|---|---|
| 平均输出变长 | 模型改变了生成长度与计算使用 | 更长本身是正确率提高的原因 |
| 出现自我检查文字 | 模型输出了这种行为模式 | 每次检查都有效，或内部过程与文字完全一致 |
| RL 期间分数提高 | 该训练路线伴随能力改善 | 无预训练先验也能同样成功 |
| 少量展示样本很精彩 | 存在这样的样本 | 这种行为普遍、稳定且占主要贡献 |

**建议的干预**：在相近预算下比较有效检查与无效重复；统计真实纠错率而非反思关键词频率；控制提示和长度再比较任务成功。

这些是进一步研究设计，不是本文已经完成的实验。

## 5. 开放权重与可复现训练之间差什么？

对本专题核对的 v1 与官方模型说明，可以分成三层：

| 层次 | 已知信息 | 尚需什么 |
|---|---|---|
| 推理使用 | 发布模型、初始化说明、一些使用建议 | 固定 revision、运行环境与完整评测 harness |
| 机制验证 | GRPO 核心公式、奖励类别、阶段与部分规模 | 自己明确的小规模数据、验证器与控制变量 |
| 完整重训 | 高层路线与部分数据数量 | 全量数据及过滤、超参数、各阶段预算、同步与恢复、精确奖励和全部中间状态 |

特别不要混用：

- 评测采样温度与训练 rollout 温度。
- 每题评测次数与训练组大小 $G$。
- 学生 SFT 配置与 671B 模型 RL 配置。
- 基座预训练成本与 R1 后训练成本。
- 社区库默认值与官方实际值。

本文没有提供足以逐项重建全部训练的公开配方。本结论限定于所读材料，不声称已经穷尽所有后续披露。

## 6. 三个值得做、但本文证据仍不充分的问题

### 6.1 冷启动究竟帮了多少？

要估计独立贡献，应固定 Base、RL 题集、奖励、预算与评测，只改变冷启动数据或初始化。最终 R1 与 Zero 的比较含多个变化，不能直接完成这种归因。

### 6.2 推理提升来自长度还是更好的计算？

可以画相同模型在不同生成预算下的成功率曲线，也可以在相同预算比较不同 checkpoint。要同时记录截断、重复与完成率，而非只报平均 token。

### 6.3 蒸馏为什么胜过某个小模型 RL？

教师提供了更强的先验行为；数据过滤和采样预算也不同。需要报告教师生成成本、学生训练成本、任务覆盖与起点，才能比较真实资源效率。

“更大模型探索、小模型学习”是合理实践方向，不是经过本篇所有必要控制实验后的普适定律。

## 7. 和业务 / Agent 工作有什么关系？

R1 给出的可迁移思路是：

> 有可检验目标时，让模型尝试、收集结果，再把高质量行为用于训练；同时单独验收用户体验与其他能力。

但业务常缺少数学题那样明确的正确答案：

- 用户偏好可能变化。
- 业务结果反馈延迟，难给每个动作归因。
- 执行失败可能来自环境，而非策略。
- 数据有隐私、许可与时间边界。
- 长任务奖励稀疏，试错可能有实际副作用。

因此不能直接把网页操作、财务处理或开放问答全部改成“结果 1 / 0 的 GRPO”。先定义受控环境、合法动作、可靠评分与失败分类。

## 8. 应该带走的研究判断

R1 的价值，是在强 Base 上展示并公开了一套有实证支持的推理后训练路线，以及成功与不成功的设计经验。

最稳妥的结论是**在明确条件下有效**。最需要避免的是把局部结果扩大成“无需数据”“无需 SFT”“只需 GRPO”“所有能力同步提高”。
