# 现代 LLM 训练流水线总览：阶段、能力域与典型工作

- 编写日期：2026-10-22；状态：已提供教材，待阅读与答疑，未运行训练或评测。
- 定位：模型结构、SFT / DPO / RL 和数据工程专题之前的**训练流程总地图**。已有课程负责局部原理，本篇解释它们怎样组成完整工程。
- 范围：以生成式、decoder-only LLM 为主，补充推理、Agent 与多模态分支。公开案例采用 OLMo 3、Qwen3 和 DeepSeek-R1，不把某一家流程当作统一标准，也不声称列尽截至今天的所有新方法。
- 快速读法：先读第 1～3 节建立地图，再按第 4 节了解团队工作；第 5～8 节处理评测、实际例子和方案差异。
- 可视化入口：[训练流水线与能力地图](2026-10-22_01_llm_training_pipeline_and_capability_map.html)；本篇 Markdown 保留完整讲解与下钻链接。

**核心认识：能力不是按阶段互斥分配的。** 预训练已经能形成知识、代码和推理基础；后续阶段通过不同数据与学习信号继续塑造这些能力。不要记成“预训练只学语言，SFT 才会编程，DPO 才会推理”。

## 1. 先分清四个维度，不要把名词排成一条流水线

| 维度 | 它回答什么 | 例子 |
|---|---|---|
| 训练阶段 / 日程 | 在整个项目的什么位置，当前要解决什么问题？ | 主预训练、mid-training、指令后训练、交付适配 |
| 数据域与能力域 | 喂什么材料，希望在哪些任务上变强？ | 科技网页、代码仓库；数学解题、编程、工具使用 |
| 学习目标 / 方法 | 用什么信号更新权重？ | next-token 交叉熵、偏好损失、奖励驱动的策略优化 |
| 工程实现 | 用哪些参数、资源和运行机制完成训练？ | 全量训练、LoRA、分布式并行、checkpoint 恢复 |

例如，“对代码任务做 LoRA SFT”同时指定了能力域、学习方式和参数更新方式；它们不是三个先后阶段。

这里还有两个不同的 domain：

- **数据 domain**：网页主题、代码语言、论文来源、语种、质量桶，主要用于整理和采样。
- **能力 domain**：知识问答、数学、代码生成、Agent 执行，主要用于目标定义与评测。

二者不是一一对应。代码数据可能影响推理能力；科技网页也有数学内容；“代码占 10%”不等于“10% 参数专门负责代码”。领域配比也不同于 MoE 的专家路由。

## 2. 一张完整地图：8 类工作包，不是固定 8 次训练

下面的编号用于组织工作。实际方案可以跳过、合并、重复或调整其中的训练环节。

```text
[0] Define goals, constraints and evaluation
                 |
[1] Prepare data, model configuration and pilot runs
                 |
[2] Main pretraining ----------------------------> Base checkpoint
                 |
[3] Optional targeted continued training / long context
                 |
[4] Demonstration learning: SFT / reasoning cold start
                 |
[5] Optional preference / reward optimization
      - DPO-style preference training
      - RL with learned rewards or verifiable rewards
      - Select, combine or iterate; not a mandatory sequence
                 |
[6] Optional distillation / compression + release acceptance
                 |
[7] Deployment, monitoring and evidence-based iteration

Across all stages:
data production + evaluation + provenance/governance + training reliability
```

### 2.1 每个工作包改变什么、交付什么

| 工作包 | 主要输入与目标 | 是否更新模型参数 | 典型交付 |
|---|---|---|---|
| 0. 目标与评测 | 定义能力、用户、风险、时延 / 成本约束 | 通常不更新 | 能力矩阵、基线、开发集与保留测试集、验收规则 |
| 1. 数据与训练准备 | 可用来源、tokenizer、架构 / 起始模型、小规模实验 | 处理本身不更新；代理实验会更新 | 数据版本、配方、训练配置、可恢复的小规模运行 |
| 2. 主预训练 | 大规模混合语料，学习通用序列规律与知识 | 更新 | Base checkpoint、训练状态、分域评测 |
| 3. 定向续训 | 调整数据质量、领域、难度、语种或上下文长度 | 更新 | 专项增强或长上下文 checkpoint |
| 4. SFT / 冷启动 | 问题到示范答案 / 动作的监督 | 更新 | 指令、工具或推理示范适配后的模型 |
| 5. 偏好 / 奖励优化 | 回答比较、采样输出、奖励或环境反馈 | 更新 | 偏好 / 策略优化后的模型及风险、成本报告 |
| 6. 交付与验收 | 候选模型、目标硬件和产品协议 | 视操作而定 | 可部署权重、模板、配置、模型卡、版本与回退包 |
| 7. 上线反馈 | 授权反馈、漂移、坏例与实际预算 | 监控不更新；新实验才更新 | 归因报告、下一版数据 / 系统修改和发布决策 |

**使用已有开放模型时，不需要重跑 1～3 的完整基座建设。** 可以从已有 Base 或 Instruct 模型进入适配，但仍需重新确认许可、评测、格式、数据治理和恢复机制。

### 2.2 哪些不应画成一条必经直线？

- **DPO 与 RL**：可以择一、组合、交替，也可以都不做。RL 不要求一定先完成 DPO。
- **SFT 与 RL**：常见方案先用示范建立可用行为，但也存在从 Base 直接进入 RL 的研究路线。
- **合成与蒸馏**：是数据生产 / 能力迁移手段，可出现在预训练、SFT 或其他阶段，不只在流水线末端。
- **长上下文**：可以在预训练后期、继续训练或后训练中安排，不是统一固定位置。
- **多模态**：需要模态接口与对齐数据，可能从头联合训练，也可能在语言模型基础上接入。
- **评测与安全**：从项目开始就参与，不是模型训练完以后才补一张报告。

## 3. 能力域 × 训练环节：每个环节通常增强什么？

以下是**常见作用机制与数据需求**，不是收益保证或贡献百分比。同一种能力可能在几个阶段重复强化，也可能伴随别的能力退化。

| 能力域 | 主预训练 / 定向续训 | SFT / 示范学习 | 偏好优化，例如 DPO | RL / 环境反馈 | 代表性验收 |
|---|---|---|---|---|---|
| 语言、知识与专业领域 | 学表达、事实关联、术语和领域结构 | 学回答方式、证据使用、领域任务与承认不足 | 偏好有依据、相关、不过度迎合的回答 | 在可核验任务上优化答案或检索行为 | 未见文档问答、证据支持、拒答与误拒 |
| 数学与推理 | 学数学文本、符号、证明、代码和问题结构 | 学解题策略、格式与可靠推理示范 | 比较解答质量；标签要关注正确性而非长度 | 利用答案 / 验证器奖励探索解法 | 答案正确率、预算匹配下的成功率与泛化 |
| 编程 | 学语法、API、注释到实现、跨文件结构 | 学按需求写代码、解释、修改和修复 | 偏好功能、规范或风格，取决于标注 | 以测试、构建或受控仓库任务反馈训练 | pass@k、独立测试、未见仓库任务 |
| 多语言 | 提供语言覆盖；优化分词和语种曝光 | 学目标语言指令、翻译及跨语言任务 | 校准语言习惯、偏好与安全标准 | 在可靠多语言奖励下优化目标任务 | 分语言能力、语言混杂、主语言回归 |
| 长上下文 | 接触长文、跨段结构；适配位置机制和训练长度 | 学长文问答、引用、多文档整合 | 比较遗漏、证据选择与忠实程度 | 有可靠奖励时强化长程决策 | 不同长度 / 位置的检索、整合、成本与退化 |
| 工具与 Agent | 代码、API 文档和流程文本提供基础 | 学工具 schema、调用条件、状态和恢复轨迹 | 比较同一状态下的动作 / 轨迹 | 在环境中探索、执行、恢复与完成任务 | 严格任务成功、违规尝试、恢复、预算 |
| 多模态 | 学模态表示与图文 / 音文对应；未必只用 NTP | 学视觉问答、OCR、定位、音视频指令 | 比较幻觉、细节正确性和用户偏好 | 对可验证感知 / 交互任务使用反馈 | 图文事实支持、OCR、时序与模态必要性 |
| 指令遵循与结构化输出 | 文档、对话与格式语料提供基础 | 强化角色、约束、JSON / schema 和条件输出 | 选择更符合要求的回答 | 可用格式规则与任务奖励进一步优化 | 指令满足率、格式合法性、内容正确性 |
| 安全、隐私与校准 | 来源治理、敏感数据处理、覆盖偏差控制 | 学拒绝、澄清、安全替代和不确定性表达 | 偏好安全且有用的响应，防止过度拒绝 | 对可靠安全 / 有用性信号优化 | 分风险测试、误拒、泄漏与越权边界 |

矩阵的读法：**按一行看能力怎样发展，按一列看该训练环节需要准备哪些数据。**

例如要增强编程：不应直接跳到“再做一次 DPO”；先判断缺的是代码知识、需求理解、输出协议、调试轨迹，还是运行环境。缺口不同，训练或工程方案不同。

安全训练也不能替代系统权限；长上下文长度不能替代长程任务成功；多语言平均分不能替代低资源语言的独立检查。

## 4. 各环节到底在做什么工作？

每节按“是什么 → 为什么 → 怎么做 → 产物与验收”展开。只给工程主线，算法公式进入已有专题。

### 4.1 工作包 0：先定义能力与测量方式

**是什么**：决定模型为谁做什么，以及什么证据算改进。不是先收一堆数据，再挑一个能涨分的 benchmark。

**为什么**：配方、偏好与奖励都会追逐目标；目标模糊，就可能只学会冗长、讨好或通过有漏洞的评分器。

**典型工作**：

- 定义能力域、输入输出、支持语言、工具权限、模型大小和推理预算。
- 建立已有模型 / Prompt / RAG 基线，判断是否真的需要改权重。
- 按来源、实体、时间或任务族隔离训练、开发和最终测试；增强样本继承分组。
- 为质量、能力回归、风险和成本设置验收规则；阈值来自业务与基线，不套统一百分比。

**交付与验收**：每个能力目标都能映射到任务、数据切片和指标；明确开发集可用于选择方案，最终测试不能反复指导训练。

### 4.2 工作包 1：数据、模型与可恢复训练准备

**是什么**：把可用内容、模型配置和计算资源变成可执行实验。来源清洗和训练系统准备通常并行进行。

**典型工作**：

- 采集获准数据，解析、去重、查污染、处理敏感信息，并保留来源与规则版本。
- 给来源 / 主题 / 语种 / 质量分桶；估计独立内容量、实际 token 量和重复曝光。
- 确定从零训练还是接续已有模型；选择规模、dense / MoE、tokenizer 和长度预算。
- 验证 tokenization、packing、文档边界、attention mask 和 loss mask。
- 用小模型或短程训练检查配方、学习率、吞吐、显存、数值稳定性和 checkpoint 恢复。

**为什么小试**：昂贵长跑之前先排除标签错位、数据重复、恢复跳样本和训练不稳定。代理实验也能帮助筛配方，但小模型的排序不保证直接迁移。

**交付与验收**：数据 manifest、代码 / 配置、消融结论与恢复测试。沿用已有模型时，不能随意换 tokenizer 而不处理词表和 embedding 兼容性。

### 4.3 工作包 2：主预训练，建立可迁移的基座能力

**是什么**：在广覆盖混合上大规模更新模型。文本自回归方案通常以 next-token 交叉熵为主，不代表所有架构都使用同一目标。

**典型工作**：执行配方和训练日程，观察分域 loss、梯度、学习率、有效 token、吞吐与失败；定期保存并评测 checkpoint，处理异常与数据问题。

**能力为何不只是语言形式**：预测代码中的下一段、数学推导的下一步、长文中的后续事实，都要求模型利用结构与上下文。NTP 可以形成任务能力，但不保证生成正确或可靠。

**交付与验收**：

- Base 权重和可恢复训练状态；后者还需要 optimizer、数据进度与随机状态。
- 留出语料损失与分域能力报告；不是只看训练 loss。
- 按预算运行选择题、生成问答、数学和代码执行评测；Base 并非只能测 PPL / BPB。

模型达到总 token 预算，不等于目标能力自动验收通过。

### 4.4 工作包 3：定向续训、退火与长上下文

**是什么**：改变后续训练材料或日程，让已有基座更适合目标。不同论文对 mid-training、continued pretraining、annealing 的命名并不统一。

| 常见工作 | 怎样做 | 特别要防什么 |
|---|---|---|
| 高质量收尾 / 退火 | 调整质量配比，配合学习率日程继续训练 | 质量分提升但内容覆盖下降 |
| 领域 / 语言适配 | 增加可靠的专业、代码、数学或目标语言材料 | 反复曝光小池、遗忘通用能力 |
| 长上下文扩展 | 适配位置机制、长序列数据与训练配置 | 只改长度参数，缺乏实际长文利用能力 |
| 能力定向增强 | 引入可靠合成、问答、推理或任务型材料 | 数据形式变化不等于训练目标已经改变 |

这些工作可以组合；继续训练可能仍使用 NTP。**数据是问答格式，不足以判断它一定属于 SFT**，还要看模板、标签范围、训练目标及项目定义。

**交付与验收**：专项 checkpoint、分域 / 分长度收益与旧能力回归；不是只提高目标域分数。动态业务事实仍可能更适合 RAG，而非不断更新模型记忆。

### 4.5 工作包 4：SFT 与推理冷启动

**是什么**：给定输入，示范应当输出的回答、代码或动作。推理冷启动是某些方案中为后续探索提供可靠起点的示范训练，不是所有模型独立必做的一站。

**典型工作**：

- 定义多轮协议、chat template、工具 schema、推理 / 最终答案格式。
- 收集和验证任务示范；通过人工、教师模型或受控执行生产数据。
- 确认监督 token 范围，避免把错误动作、未来 observation 或内部 grader 答案当作正确输入。
- 控制领域、难度、长度、正常 / 边界样本与回放配比；选 checkpoint 并检查遗忘。

**能力作用**：不仅统一格式，也能学习新行为与解决策略；但不保证复制全部教师能力。错误示范同样会被学习。

**交付与验收**：指令或轨迹适配模型、数据卡与格式配置。既测格式合法，也测回答正确、工具参数与任务成功；token loss 下降不是唯一验收。

### 4.6 工作包 5A：偏好数据与 DPO

**是什么**：在相同输入条件下，用 chosen / rejected 的相对偏好塑造输出。DPO 是一条偏好优化路线，不要求单独训练显式 reward model。

**典型工作**：生成可比较候选，设计标注规则，校准人工 / judge / 测试信号，处理分歧、长度偏置、近重复与任务覆盖，再训练并独立验证。

**能力作用由偏好决定**：

- 只比较风格，不能自动推断功能正确性提升。
- 用可靠测试区分程序，可传递正确性偏好。
- 比较工具动作必须对齐输入状态、权限和可见信息，不能随意配对不同任务。

**交付与验收**：偏好数据、优化后模型、独立质量 / 成功率 / 风险报告。偏好胜率提升，不必然代表事实、代码或整体任务正确率提升。

### 4.7 工作包 5B：奖励建模、RLHF、RLVR 与环境训练

**是什么**：模型按策略产生输出或动作，根据奖励优化。这里需要区分“奖励怎么来”和“参数怎么更新”。

| 名词 | 描述的轴 | 典型工作与边界 |
|---|---|---|
| Reward model | 评分器 | 训练 / 校准人类偏好代理，检查偏置、泛化和被利用的漏洞 |
| RLHF | 人类反馈路线 | 经典做法用偏好训练奖励模型，再优化语言模型；具体实现可不同 |
| RLVR | 可验证奖励来源 | 用答案检查、测试或其他验证器给分；规则也可能不完整 |
| PPO / GRPO | 策略优化算法 | 管理采样、概率、优势、更新约束与数值稳定性；不等于奖励定义 |
| 环境 / Agent RL | 交互任务形态 | 维护初始状态、工具、观察、终止和严格结果判定 |

**典型生产循环**：采样任务 → rollout → 验证 / 打分 → 过滤无效运行 → 策略更新 → 独立评测 → 按需再采样。

团队要同时处理模型 rollout 成本、环境吞吐、版本同步、长度和奖励偏置。不能把任意历史轨迹直接当成当前策略的 on-policy 数据。

**能力作用**：在可探索、可反馈的任务上强化策略；数学、代码、指令约束与工具环境各有不同验证方式。长输出、奖励增长或更高训练成功率，都不能单独证明泛化。

**交付与验收**：策略 checkpoint、训练分布、奖励 / 环境版本、严格任务表现与推理成本。训练奖励和最终验收应有足够独立性，不能只让同一个有漏洞的 grader 自证成功。

### 4.8 工作包 6～7：能力迁移、发布与反馈

**是什么**：把研究 checkpoint 变成可消费、可维护的模型服务，再决定下一轮修什么。

| 工作 | 是否训练 | 产物与验收 |
|---|---|---|
| 蒸馏 | 通常训练学生模型 | 教师输出 / 分布或指导数据；验证学生能力和教师 / 学生总成本 |
| 模型合并（可选） | 合并本身通常不做梯度更新 | 验证兼容性、合并后能力与退化；不能假定两个优点自动相加 |
| 压缩 / 量化 | PTQ 不做常规权重梯度训练；QAT 会训练 | 量化配置、质量、显存、吞吐、延迟与目标硬件验证 |
| 发布包与最终评测 | 评测不更新权重 | 权重 / adapter、tokenizer、模板、推理配置、模型卡、风险和回退 |
| 上线监控与迭代 | 监控不自动训练 | 漂移、误差归因、授权数据回流和下一版实验 |

蒸馏不只用于最后压缩，也可在早期生成能力数据。线上日志也不能不经授权、筛选和集合隔离就直接回流训练。

先区分模型、检索、工具、权限、模板和环境错误；需要训练时再回到对应工作包，不是每次坏例都重跑整条流水线。

## 5. 评测是另一条贯穿主线，不由训练阶段限定

| 评测层次 | 具体测什么 | 可以在哪些阶段使用 |
|---|---|---|
| 概率 / 损失 | 留出文本 PPL、参考答案 / 代码 BPB | 代理实验、预训练、继续训练、后训练诊断 |
| 候选选择 | 比较候选续文，统计选对比例 | Base 和后训练模型；注意 prompt 与归一化口径 |
| 自由生成 | 生成答案，再按规则 / 人工 / judge 判分 | Base 也可以测，不必等 SFT |
| 可执行程序 | 生成代码，由外部测试器执行，统计 pass@k | Base、SFT、偏好和 RL 模型均可测 |
| Agent 闭环 | 调工具、读取反馈、恢复并满足最终状态 | 配有相容运行框架的模型 / 系统 |
| 发布与风险 | 能力回归、隐私、安全、时延和预算 | 每次候选发布，必要时中间 checkpoint 也测 |

**“模型生成代码，外部评测器运行测试”不等于“模型会自己调用工具、根据报错修复”。** 前者可以是单次补全；后者需要模型与 Harness 的执行闭环。

BPB 与 PPL 都来自参考文本的负对数似然，但归一化和变换不同。概率更好不保证生成 / 执行成功率同步提高，尤其 teacher forcing 不暴露全部自生成错误。

OLMo 的 Base Easy 包含 BPB 和候选评分配置；Base Main 另含生成、数学和代码执行任务。低成本信号适合筛配方，昂贵任务评测用于检查真实目标能力；不能概括为“预训练只看 BPB，后训练才看成功率”。

## 6. 同一个代码能力目标，怎样穿过整条流水线？

教学场景：**从 CSV 汇总每位客户的销售额，缺列时明确报错。** 以下是工作示例，不是已实现或实测项目。

| 环节 | 训练 / 系统团队具体做什么 | 模型可能新增或强化什么 | 怎么证实 |
|---|---|---|---|
| 目标与准备 | 定义字段、空值、金额类型、报错协议和独立用例 | 此时尚未改变能力 | 标准与测试可执行、数据划分独立 |
| 主预训练 | 混入可靠程序、库文档和数据处理材料 | Python / CSV 知识、API 和程序结构 | 代码补全、知识与基础执行评测 |
| 定向续训（按需） | 增加相关领域程序、复杂表格 / 数据处理内容 | 专业模式和难例覆盖 | 同预算对照、旧代码能力回归 |
| SFT | 示范需求 → 完整程序，包含边界条件和正确报错 | 从自然语言需求到可用实现 | 未见数据集上的功能和边界测试 |
| DPO（按需） | 同一需求下比较正确程序与忽略空值的程序 | 偏好更符合规范的实现 | 独立测试，不只复用制作偏好的用例 |
| RL（按需） | 对采样程序执行受控测试，将结果用于奖励 | 探索更高成功率的程序策略 | 保留测试、鲁棒性与成本 |
| Agent 分支（按需） | 提供读文件、编辑、测试接口及真实恢复轨迹 | 选择工具、利用错误反馈、修复后核验 | 在未见任务 / 环境中严格验收 |
| 发布 | 固定模板、版本、权限和推理预算 | 不因部署就自动增加模型能力 | 原始与部署模型对照、回退可用 |

这里没有“编程能力从零突然出现在 SFT”的分界线。也不需要为了一个 CSV 任务默认把 DPO、RL 和 Agent 全部做完。

## 7. 两条可选能力分支，需要单独准备什么？

### 多模态分支

语言模型不会因为文本中出现“图片”二字就获得视觉输入能力。需要图像 / 音频输入接口、编码器或相应表示，以及对齐和任务训练数据。

常见模块化路线是已有语言模型 + 模态编码器 / 连接器 → 对齐训练 → 多模态指令训练 → 按需偏好 / 奖励优化。也有从头联合训练路线，训练目标可能结合对比、重建或生成，不限于文本 NTP。

典型工作：配对与时序对齐、视觉分辨率 / 音频长度预算、模态特定清洗、OCR、区域与时间标注。验收要检查模型是否真的使用模态证据，以及细节、错配和幻觉。

### 推理与工具分支

推理模型可以通过高质量推理示范、定向数据和结果奖励增强；不要求一定使用 DPO，也不应把链条越长当作越强。

工具 / Agent 需要任务与环境数据：可见状态、可用工具、参数、执行结果、授权和终止。环境和验证器必须先可靠；否则训练会学习错误反馈或利用判分漏洞。

普通测试器只在模型生成之后评分；Agent 训练还可能让测试反馈成为后续决策的 observation。**执行反馈既可用于训练，也可只用于评测；是否据此更新权重决定它是不是训练信号。**

## 8. 用公开方案校准地图：不存在唯一标准顺序

| 公开案例 | 官方披露的路线 | 对本地图的启示 |
|---|---|---|
| OLMo 3 | Base 数据分为主预训练、mid-training、长上下文；模型卡列出 Base → SFT → DPO → RLVR 检查点 | 这是一条较完整、可观察阶段产物的路线，不是通用必经顺序 |
| Qwen3 | 预训练逐步加强知识 / 代码 / 推理及长上下文；后训练含长 CoT 冷启动、推理 RL、思考模式融合、通用 RL | SFT 类型的学习可以再次出现在 RL 之后；能力增强不只在后训练 |
| DeepSeek-R1 / R1-Zero | R1-Zero 从 Base 直接做 RL；R1 使用冷启动并包含两轮 SFT、两轮 RL；另有蒸馏模型 | “RL 前必做 SFT”不是算法定律；可行路线仍有可读性与稳定性取舍 |

资料使用边界：

- 本节核对公开官方说明，未复现其完整训练，不给各阶段虚构贡献率。
- 品牌、模型大小、checkpoint 与发布时间必须对应；不能混用不同版本的结果证明某阶段的因果收益。
- 公司对 mid-training、post-training 的命名会有差别。**看输入、loss、更新方式与评测，不只看阶段名称。**

## 9. 团队协作：每轮训练需要哪些可核对产物？

| 工作线 | 核心责任 | 对下游的交付 |
|---|---|---|
| 能力 / 评测 | 目标、独立测量、误差归因、退化与预算 | 能力矩阵、固定评测协议、实验结论 |
| 数据 / 标注 | 来源、质量、覆盖、重复、示范与偏好 | 数据版本、血缘、质量卡、可消费格式 |
| 算法 / 训练 | 目标函数、配方、优化、checkpoint 选择 | 可复现配置、权重、恢复状态、消融 |
| 平台 / 环境 | 训练可靠性、rollout、测试和工具环境 | 资源、吞吐、恢复能力、环境版本与日志 |
| 治理 / 发布 | 使用边界、敏感数据、审批、部署与回退 | 批准范围、发布包、风险说明、处置机制 |

一轮实验至少回答六个问题：从哪个 checkpoint 出发？用了哪版数据？改了什么目标或配方？实际花了多少预算？在哪个独立评测上变好 / 变差？产物怎样恢复、部署或回退？

数据飞轮的闭环是“失败归因 → 提出数据 / 模型 / 系统假设 → 受控验证 → 决定发布或拒绝”，不是“把所有线上日志倒回训练集”。
