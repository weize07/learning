## 1. Embedding 在 RAG 中解决什么问题？

用户问“什么时候能处理完”，文档写“通常需要三个工作日”。字面词汇可能不相同，但两者存在检索关系。

Embedding 模型将文本映射成固定维度的数值向量，训练目标使有用的文本关系能通过向量分数体现。它不是人工指定每一维代表“时间”“订单”等概念。

```text
离线：
片段 1 → 文档编码 → 向量 1 + 片段 ID
片段 2 → 文档编码 → 向量 2 + 片段 ID
……

在线：
用户问题 → 查询编码 → 查询向量
                          ↓
               与允许访问的片段向量比较
                          ↓
               取候选 ID → 回取原文
                          ↓
                  后续重排与生成
```

Embedding 向量用于检索，原文用于回答与引用；不从向量无损还原资料。

## 2. Token embedding 与检索 embedding 有什么区别？

你之前学习的是模型内部每个 token 的表示。文本检索通常需要整段文本的一个向量：

| 表示 | 常见形状（省略 batch） | 用途 |
|---|---|---|
| Token / 隐藏状态 | $[n,d_{\text{model}}]$ | Transformer 内部处理各位置 |
| 文本检索向量 | $[d_e]$ | 比较一条问题或一个片段 |

检索向量可能由 token 表示通过均值池化、特定位置池化、投影等形成，具体按模型设计。不是任意把一个聊天模型最后一行拿出来，就保证成为好的检索向量。

输出维度 $d_e$ 与模型参数量不同，可能也与 $d_{\text{model}}$ 不同。例如 [Qwen3-Embedding 系列](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)提供不同输出维度；改变维度需要遵循该模型支持规则，不随意截断任何 embedding。

## 3. 问题与片段需要兼容的编码方式

问题通常短，资料片段通常长，两者不必措辞相似。这是非对称检索：希望找到“回答这个问题的片段”，不是只找另一个相似问题。

模型可能使用：

- 同一个编码器，query 与 document 使用不同前缀或指令。
- 两个不同但共同训练、输出空间兼容的编码器。
- 不同的任务路由或 pooling。

两个任意模型输出都是 1024 维，不代表可以直接比较。query / document 编码需属于匹配的空间与任务配置。

使用前核对：

1. 是否适合中文、技术文档、代码等任务。
2. query 指令、document 前缀是否有明确要求。
3. 最大输入长度、pooling 与截断行为。
4. 训练或推荐的相似度函数、是否归一化。
5. 模型与 tokenizer 的固定版本。

模型升级或这些配置变化后，旧索引可能不再兼容，需要重建或版本隔离，不能只更新查询模型。

## 4. 相似度怎么计算？

### 4.1 余弦相似度：比较方向

$$
\operatorname{cos}(q,d)
=\frac{q\cdot d}{\|q\|_2\|d\|_2}
$$

非零向量下，范围为 $[-1,1]$。越大表示这个分数函数下方向越接近，但不自动等于答案支持度。

用二维示意：

$$
q=[1,0],\qquad d_1=[2,0],\qquad d_2=[1,1]
$$

$$
\operatorname{cos}(q,d_1)=1,\qquad
\operatorname{cos}(q,d_2)=\frac1{\sqrt2}\approx0.7071
$$

d1 较长，但方向与 q 一致。真实 embedding 维度更多，不能把这两个坐标当成可解释的语义标签。

零向量的余弦分母为零，应视为异常或按明确约定处理，不能静默返回一个看似正常分数。

### 4.2 点积：同时受到长度影响

$$
s(q,d)=q\cdot d
$$

若 query 和 document 都已 L2 归一化为单位长度，点积等于余弦。

归一化使用：

$$
\bar d=\frac d{\|d\|_2}
$$

它与 RMSNorm 不同：单位长度归一化让长度为 1；忽略仿射与稳定项的 RMSNorm 让 RMS 为 1，长度为 $\sqrt{d_e}$。

不要把用点积训练的模型任意改成余弦后假设排序不变，除非归一化等条件成立。

### 4.3 欧几里得距离

$$
\operatorname{dist}(q,d)=\sqrt{\sum_r(q_r-d_r)^2}
$$

越小越接近。若两向量都为单位长度：

$$
\|q-d\|_2^2=2-2(q\cdot d)
$$

此条件下距离与余弦排序对应；未经归一化不能直接这样判断。

## 5. 检索的矩阵形状

有 N 个片段，各向量宽度为 $d_e$，按行堆叠：

$$
D\in\mathbb R^{N\times d_e}
$$

一条查询：

$$
\underbrace{q}_{1\times d_e}
\underbrace{D^{\mathsf T}}_{d_e\times N}
=\underbrace{s}_{1\times N}
$$

得到每个片段的分数，按大到小取 top-k（这里假设点积类高优分数）。若为余弦，可先正确归一化再做这个乘法。

B 条独立查询则为 $[B,d_e]@[d_e,N]\to[B,N]$。

这与 Attention 的点积形状有相似之处，但职责不同：

- 检索：比较文本向量，取得片段 ID 和原文。
- Attention：在模型层内计算 Q/K 分数，汇总 V。

检索不必做 softmax；即使转为 softmax，也不自动成为“文档正确概率”。top-k 是候选数量，不表示质量或完整证据已经达标。

## 6. Embedding 为什么能学到检索关系？

一种常见训练样本为 query、正例片段与若干负例：

```text
query：标准申请材料不完整时，从何时开始计时？
正例：补齐材料后开始计时的规则
负例：加急申请规则、查询进度说明等
```

编码器通常分别计算 query 与 document，得到相似度。一个简化的对比目标为：

$$
\mathcal L=
-\log
\frac{\exp(s(q,d^+)/\tau)}
{\exp(s(q,d^+)/\tau)+\sum_j\exp(s(q,d_j^-)/\tau)}
$$

其中 τ>0 是训练温度，调节候选分数尺度，不是生成采样温度。损失推动正例在这些候选中获得更高相对分数；不同模型还有其他训练目标。

常见负例：

- 随机负例：可能太容易。
- 同 batch 其他文档：提高训练效率，但可能有 false negatives。
- Hard negatives：检索得分高、实际却不适用的片段。

**False negative** 是被标成负例、实际上也支持问题的内容。不同版本、重复段落、多证据答案尤其要检查，不能把所有非唯一正例都当错误片段。

训练数据与评测按相关组划分、检查近重复。先用预训练检索模型建立基线，有领域差距与可信数据后再考虑训练。

## 7. Embedding 检索与 Re-rank 如何分工？

| | 常见 bi-encoder 检索 | 常见 cross-encoder 重排 |
|---|---|---|
| 模型输入 | query、document 分别编码 | query 与候选 document 一起输入 |
| 文档表示 | 可以提前计算并建索引 | 典型情况下须按本次 query 重新评分 |
| 比较范围 | 面向大候选库 | 对初步召回的较小候选集 |
| 相互交互 | 通过向量相似度 | 可通过联合编码形成细粒度交互 |

这是常见设计，不是所有 reranker 都是 cross-encoder。重排也不保证一定比检索分数更好，需独立评测。

下一阶段的 Re-rank 数据与目标函数会详细展开；不能直接认为所有模型都套上面的 embedding 对比目标。

## 8. 索引与 ANN：概要即可

小库可以精确比较所有向量；规模大时常用 ANN（近似最近邻）索引减少检索成本。

ANN 可能漏掉精确搜索能找到的高分片段，因此应区分：

- 表示不好：即使精确搜索也找不到所需片段。
- 近似索引误差：表示分数合理，但 ANN 漏掉候选。
- 过滤 / 权限 / 版本：允许集合或检索执行不正确。

向量数据库不是 embedding 模型；它管理向量、元数据与检索等能力。具体索引算法、分布式部署当前只提供概要，不作为主线深挖。

## 9. 常见失败与评测

| 失败 | 例子 / 排查 |
|---|---|
| 精确实体混淆 | 型号 A 与型号 B 文本很相似，向量误召回 |
| 否定或条件丢失 | “支持”与“不支持”主题相似但结论相反 |
| 长片段截断 | 关键条件在 embedding 输入尾部被丢弃 |
| 多证据缺一 | 检索到时长，没有检索到工作日定义 |
| 空库也必须返回 k 条 | 无关片段相对排名高，被误当充分证据 |

检索评测可以检查：

- 必要证据在 top-k 中是否出现、联合覆盖是否足够。
- 相关候选排名，例如 MRR / nDCG；具体定义与多正例处理后续展开。
- 按语言、实体、长度、不可答等类型拆分。
- 最终生成正确性、引用支持与成本。

任何语义相似度阈值都需按模型、任务和验证集校准，不通用地规定“0.8 以上就有答案”。
