先读第 1～4 节的模型与数据，再看第 5～7 节的损失。本篇回答用户提出的两个重点：训练数据如何准备，以及目标函数如何选择。

## 1. 先定位：重排是在已有候选中选出更有用的证据

```text
问题 → BM25 / 向量 / 混合召回
                      ↓
              候选片段及原文
                      ↓
       reranker 对 query + candidate 评分
                      ↓
             排序 / 筛选 / 证据组织
                      ↓
                  LLM 回答
```

只重排已有候选，不能找回未召回的证据。召回预算、最终证据数量和长度预算分别配置，不用一个 top-k 参数概括全部阶段。

目标不是让“主题最像”的片段排第一，而是根据任务定义，把有用的候选排得更好。版本、权限与实体过滤仍须由可靠流程处理，不能只交给学习评分器。

## 2. 常见模型：Cross-encoder

Bi-encoder 分别编码 query 和 document，比较向量。Cross-encoder 把两段文本一起输入，允许联合建模：

```text
query + 分隔标记 + candidate 文本
                   ↓
              Transformer
                   ↓
           表示聚合 / 打分头
                   ↓
              一个分数 s(q,d)
```

常见 encoder 架构可通过指定位置表示与标量头评分；LLM 型 reranker 也可根据特定 token 概率、评分头或其他协议打分。具体模型需使用其模板与分数提取规则，不强行套一个格式。

联合输入通常可获得更细的 token 交互，但每个 query-candidate 都需计算，文档不能像普通 bi-encoder 那样提前存一份向量后解决所有评分。

单标量分数不必在 0～1，也不自动是正确概率。用 sigmoid 输出也不等于经过概率校准。重排不生成最终业务答案。

## 3. 先定义标签，再生成训练数据

### 3.1 相关与支持不是同一个标准

虚构问题：

> 标准申请材料不全时，从何时开始计时？

候选：

| 片段 | 内容 | 判断 |
|---|---|---|
| A | 标准申请从材料补齐后开始计时 | 直接支持问题 |
| B | 标准申请通常需要三个工作日 | 同主题，但没有回答起算点 |
| C | 加急申请收到材料即开始计时 | 主题相似，但不适用标准申请 |
| D | 查询进度需要申请编号 | 相邻业务，不支持本题 |

如果目标是证据排序，可以定义等级：

- 0：不支持 / 不适用。
- 1：提供必要的部分证据，需要与其他片段结合。
- 2：单段充分支持。

**不是所有主题相关片段都应标 1。** 本例 B 是否有其他用途取决于完整问题；针对起算点，它可标为不支持。若采用主题相关性目标，应另写规范，不混用两种标签语义。

多片段问题的各正例可能都只有部分支持。不要强迫所有问题拥有一个“充分支持的唯一正例”，也不要因单段不完整就把必要证据标为负例。

### 3.2 元数据规则先处理

旧版本规则、不同产品和未授权内容不能仅靠一个分数解决。定义允许资料范围与版本策略后，在这个候选集合上标注和训练。

可用不适用版本作为安全的训练对照，但不得让未授权内容进入用户模型上下文。若问题明确问历史版本，旧资料也可能是正例。

## 4. 数据怎么准备？

### 4.1 从训练查询与实际召回候选出发

1. 收集真实且有授权的问题，或基于训练文档生成问题并审核。
2. 确认必要证据位置与答案支持标准。
3. 使用当前 BM25 / 向量 / 混合基线为训练问题召回候选。
4. 对候选标注，挖掘高分但不支持的错误片段。
5. 必要时补入遗漏正例，用于训练；仍单独记录召回是否漏掉它。
6. 保存 query、候选原文、标签、来源版本、检索配置和审核状态。

这让训练面对的候选更贴近线上。只把正确答案与完全无关随机文本配对，可能过于容易。

点击或用户停留仅是线索：存在展示位置、流量与界面偏差，不能直接把“没点击”当负例或“点击了”当充分支持。自动合成 / LLM 标签需要独立抽查。

### 4.2 Hard negatives 是什么？

对当前检索器容易混淆、却不满足任务的候选，例如：

- 同词不同实体。
- 主题相同但适用条件不同。
- 当前问题不接受的旧版本。
- 关键数值或否定不同。
- 看似相关但缺少所问事实。

困难负例也可能是漏标正例（false negative）。尤其重复文档、同义表达和多证据问题，必须审核。

不要全部训练最难样本。混合常规与困难候选，检查数据质量、问题覆盖、重复曝光和实际监督量，不把难度当自动质量标签。

### 4.3 数据结构

```json
{
  "query_id": "q_standard_start",
  "query": "标准申请材料不全时，从何时开始计时？",
  "document_group": "policy_group_train",
  "candidates": [
    {"chunk_id": "A", "text": "标准申请从材料补齐后开始计时。", "support_grade": 2},
    {"chunk_id": "B", "text": "标准申请通常需要三个工作日。", "support_grade": 0},
    {"chunk_id": "C", "text": "加急申请收到材料即开始计时。", "support_grade": 0}
  ]
}
```

此为自编教学样本。正式数据还需文档版本、候选来源、审核信息。标签不应被拼进待测 reranker 的输入。

划分按 query 家族、文档 / 实体和近重复关系处理。同一问题的不同候选或轻微改写不能随意跨训练与测试。分组策略需匹配泛化目标，并保持各集合覆盖，不机械认为只有一种合法划分。

### 4.4 人工对整组候选排序

可以给定 query 和 5 个候选，让标注者给出完整或部分排序，例如：

$$
D_3\succ D_1\succ(D_2=D_5)\succ D_4
$$

$\succ$ 表示优于，括号中的等号表示同级；不是要求任何两份文档都能分出高低。允许无法判断、部分排序与全部不相关，并规定排序依据是主题相关、证据支持还是任务用途。

列表排序可以转为：

- **Pairwise**：提取明确的先后关系；同级项不强行制造正负关系。不要因一题能派生很多对，就让它获得未声明的更大训练权重。
- **Listwise**：使用能接收排列或部分排列的目标。例如无平局的排序 $\pi$，一种 Plackett–Luce 形式为：

  $$
  \mathcal L_{\text{order}}
  =-\sum_{k=1}^{M}
  \log\frac{\exp(s_{\pi_k})}
  {\sum_{\ell=k}^{M}\exp(s_{\pi_\ell})}
  $$

  每步让排在前面的候选在剩余候选中获得更高相对分数。平局 / 部分排序需要相应扩展或转换，不直接套这个严格排列公式。
- **等级标签**：可以另请标注者给各文档相关性等级。仅有排序不能唯一推出绝对标签或差距，不把第一名自动标为充分支持、最后一名自动标为无关。

给一组文档排序，是标注形式；训练时使用 pairwise 还是 listwise，是另一项选择。人工整组比较同样可能有位置、疲劳与长文本偏差，可随机展示顺序、规定 rubric、复核模糊案例。

### 4.5 在线行为、模型代理与执行反馈

“online 动作代理”可指不同机制，应分别记录：

| 反馈来源 | 如何产生排序线索 | 主要局限 |
|---|---|---|
| 用户点击、选择、采纳 | 用户在已展示候选上采取动作 | 展示位置、是否被看到、用户目的与选择偏差；未点不等于负例 |
| LLM / Agent 作为标注者 | 对 query 和候选读原文、逐项或整组比较 | 是模型生成的弱 / 银标签，不是独立真值；有顺序与风格偏差 |
| Agent 在环境中完成任务 | 改变提供的证据，观察正确回答、测试通过或任务成功 | 测到的是证据与特定策略 / 工具组合的用途；成本高、结果有随机性和多文档交互 |

例如有 10 个候选，可以固定问题、生成模型、工具、预算与评分，在安全环境中分别只提供 D1、D2 等，比较完成率。每种条件重复执行比只运行一次更可靠，但单文档不能完成任务不意味着该文档无用：D1 可能必须和 D2 一起提供。

对于实际用多片段上下文的系统，也可比较：

```text
提供证据集 S → 测任务效果
移除其中某段 d → 再测
观察差异 → 得到这段在该集合下的边际用途线索
```

这不是文档的永久“真实分数”。结果依赖问题、其余证据、顺序、策略能力、工具和预算；重复片段会替代彼此，互补片段可能单独都低分。未经控制的上线相关性不等于因果贡献，完整边际贡献计算也可能很昂贵。

工程上应：

1. 区分曝光、点击、明确采纳与可验证成功，不将它们合成一种无说明的标签。
2. 记录候选集合、展示 / 输入位置、模型与评分版本、失败及随机配置。
3. 行为数据按需要用随机化、实验分配或倾向权重等处理偏差；这些方法都有适用条件。
4. Agent 执行实验在受控环境中进行，避免为标注反复触发真实副作用。
5. 用独立人工证据标签与留出任务评测校准代理信号，不用同一个 Agent 自生成、自判分后宣称排序客观。

这些反馈可转换为分数、成对偏好或列表标签用于离线训练；也可以研究在线排序策略优化，但后者是另一套训练设计，不是调用一个在线 Agent 就自动得到 PPO / GRPO。

### 4.6 如果目标是 CTR，点击就是直接监督目标

前面的提醒不是说在线信号不重要。要区分两个任务：

- **证据重排**：希望资料能支持答案，点击只是可能相关的代理。
- **点击率预测**：希望估计在指定展示条件下用户会不会点击，点击本身就是观测标签。

例如每条记录包含 query、候选、用户 / 会话的合规特征、位置与展示环境，记这些特征为 z：

$$
\widehat p=\Pr(\text{click}=1\mid z,\text{eligible exposure})
$$

曝光后观察到点击，y=1；按事先规定的观察窗口、可见性与归因规则确认未点击，y=0。没有真正曝光、标签尚未成熟或日志缺失的候选，不直接当成可靠负例。

可以用 BCE：

$$
\mathcal L_{\mathrm{CTR}}
=-\left[y\log\widehat p+(1-y)\log(1-\widehat p)\right]
$$

它与 pointwise BCE 的数学形式相同，但标签含义不同：这里预测行为概率，不是在监督“事实支持”。CTR 模型可包含用户、时间、展示位置等上下文，不必只用 query-document 文本 cross-encoder。

在线日志的价值是规模、真实用户需求与持续适配，可以用于：

- CTR 或采纳率等行为预测。
- 排序训练中的偏好 / 反馈特征。
- 评估新排序的真实业务收益与分布漂移。
- 与明确完成结果结合，建立更贴近产品目标的监督。

**位置偏差在不同目标中的含义不同：**

1. 预测当前展示机制下的点击率：位置是有用的上下文特征，不应为了“去偏”就盲目删除。
2. 比较文档本身的吸引力 / 相关性，或部署新排序：位置与曝光选择可能混杂，需要随机化、曝光模型、倾向加权等合适设计；简单删除位置特征也不自动消除偏差。

未曝光文档的行为不能仅凭旧日志直接观察；新排序会改变曝光分布。时间划分、用户 / 会话相关性与在线 A/B 都需要处理，不能只随机切日志并看离线 AUC，就宣布新排序会提升线上 CTR。

行为预测可关注 log loss、AUC 与概率校准，按任务拆分；类不平衡和负例下采样会影响概率与指标，需要记录采样 / 加权并校准，不把下采样后的原始输出直接当真实 CTR。

RAG 产品可以联合关注“用户点击 / 采纳”和“答案正确 / 证据支持”，但不能假定二者等价。可以把点击作为业务目标之一，同时将事实支持、权限和关键风险作为质量条件；不同尺度指标的权重需实验，而不是任意相加。

## 5. Pointwise：单独判断每个候选

二分类训练样本为：

```text
(query, candidate, y)，y ∈ {0,1}
```

模型输出分数 s，令 p=σ(s)，用 BCE：

$$
\mathcal L_{\text{point}}
=-\left[y\log p+(1-y)\log(1-p)\right]
$$

实际通常用稳定的 logits 版本计算，不先求概率再取 log。

如果定义 y=1 为“对任务有用”，就必须明确部分支持是否算有用；不能丢掉标签规范。

优点是格式简单、便于建立训练基线；局限是没有直接比较同题候选的相对排序，正负比例与标注会影响结果。

分级标签可采用多分类、回归或其他设计。用 MSE 回归 0/1/2 是一个候选，不代表等级差天然等距，也不自动优化 nDCG。

## 6. Pairwise：比较同题两个候选

训练样本：

```text
(query, d+, d-)，正例应排在负例前
```

分别算 s+、s-，一种常见 logistic 目标：

$$
\mathcal L_{\text{pair}}
=-\log\sigma(s^+-s^-)
$$

与你学过的 Bradley–Terry 偏好损失形状相同，但这里学习的是 query-document 排序，不是生成模型完整回答的 DPO 目标。

例如分数差为 2，损失约 0.1269；分数差为 −2，损失约 2.1269，推动排序正确。

另一种 margin ranking / hinge：

$$
\mathcal L_{\text{margin}}
=\max(0,m-s^++s^-),\qquad m>0
$$

正确差距达到 margin 后，该项不再要求继续拉大。它分段可导，可用次梯度训练；不是必须处处光滑才可训练。

注意平局、标签噪声与不同等级。不要从每组 n 个候选盲目制造所有配对：大量重复容易改变问题权重，误配也会放大错误。

## 7. Listwise / 组级候选目标：同时看一组排序

一个简单候选集 softmax 目标，假设一题有一个已确认正例：

$$
\mathcal L_{\text{group}}
=-\log\frac{\exp(s^+/\tau)}
{\sum_{j=1}^{M}\exp(s_j/\tau)}
$$

模型仍可分别编码每个 query-candidate，只是损失将一组分数一起比较；“组级损失”不代表模型一定把整组文档拼进同一次输入。

此目标与对比训练相似，但 scorer 可以是 cross-encoder。不同文献会将它归为候选分类 / 对比或 listwise 类目标，它不是全部 Learning-to-Rank 的唯一 listwise 定义。

有多个正例时，不能把其余正例都放进错误候选：

- 可设计目标分布，对所有有效正例分配权重，用交叉熵拟合。
- 可用多正例概率质量或其他排序目标。
- 等级与重要性如何映射需明确，不保证这些方案学习相同的排序。

真正的 listwise 方法还包括对列表分布或排列建模。入门先理解“逐个判、成对比、整组比”的区别，不急着实现所有变体。

## 8. 目标函数怎么选？

| 已有数据 / 需求 | 候选起点 |
|---|---|
| 可靠 query-candidate 二元标签 | Pointwise BCE，简单可检查 |
| 同题相对顺序更可靠 | Pairwise logistic / margin |
| 每题有完整候选与正例 / 分级标签 | 组级交叉熵或合适 listwise 目标 |
| 多片段协作 | 明确部分支持与联合覆盖，必要时另做证据集选择 |

不要把“listwise 更复杂”理解为一定效果最好。保持模型、候选、预算与评测可比，试最简单可用目标。

训练数据、模型形式与损失是三种选择：相同 cross-encoder 可使用不同目标，相同对比形式也可以用于不同编码结构。查看实际实现与输出激活，不只看方法名称。

## 9. 如何评测与避免假收益？

分别检查：

- **候选覆盖上限**：需要的证据是否已经进入重排候选。
- **排序质量**：MRR、nDCG、top-k 证据覆盖。
- **生成影响**：条件完整性、回答正确、引用支持与拒答。
- **成本**：候选数、输入长度、延迟与预算。

常见指标：

- MRR：每题第一个符合定义的相关结果的排名倒数，再对问题平均；未找到按规则计 0。它不反映全部多证据是否齐全。
- nDCG@k：按位置折扣累积相关性增益，除以该题理想排序的 DCG。等级到增益的规则固定；没有任何正例时按明确约定处理，不默认满分。
- 证据覆盖：单正例可看命中，多正例需区分至少一个、各必要片段或完整证据集覆盖。

不同系统若使用不同候选预算、截断规则、chunk 或最终上下文大小，报告差异。配置用验证集选择，最终测试留出。

排序模型训练损失下降不等于生成变好。只把候选排得“主题更相关”，可能反而挤掉必要条件。单片段排序也可能重复选择同一信息，需要后续去重、父段展开或证据组合。

## 10. 实践建议与资料

先用一个现成、适合语言与任务的 reranker 建基线，记录失败类型。确实存在领域差距且有可信标签时，再微调，而不是默认必须自训。

[Sentence Transformers 的 reranker 文档](https://www.sbert.net/examples/cross_encoder/training/rerankers/README.html)（2026-10-12 核对）展示 BCE 与多负例候选目标。[CrossEncoder losses](https://www.sbert.net/docs/package_reference/cross_encoder/losses.html)提供不同实现入口；实际 API、激活、缩放与负例处理按固定版本核对。
