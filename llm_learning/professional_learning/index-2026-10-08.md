# Agent / LLM 工作能力提升与实践手册（2026）

> 能力覆盖：LLM 算法、GenAI / Agent 应用、推理部署、AI 平台工程
> 学习目标：以提升实际工作能力和长期知识积累为主线，通过原理理解、源码阅读、可复现实验与项目复盘验证进步。外部参考资料保留真实标题与链接，其题库或招聘视角不作为学习目标。
> 核心变化：不是“会不会用 LLM”，而是“能不能把不确定性系统做成可观测、可评估、可回滚、可上线的生产系统”。

## 个人学习方向与教程取舍（2026-10-17 更新）

本索引保留完整知识地图，但不代表所有方向都要以相同深度学习。后续教程与每日学习记录按以下优先级组织：

- **第一优先级：LLM 应用层与算法 / 数据。** 重点学习 Transformer 与训练目标等必要基础、RAG、Agent、工具调用、微调与后训练原理，以及数据采集 / 清洗 / 去重、训练集与评测集构建、数据泄露防范、误差分析、效果迭代。围绕实际任务展开原理、示例、实验、失败模式与评估方法。
- **第二优先级：Infra。** 重要知识点保留概要学习内容与资料索引，理解解决什么问题、基本机制、对延迟 / 吞吐 / 显存 / 成本的影响，以及何时需要与 Infra 团队协作；默认不深入 CUDA kernel、通信实现、推理引擎源码或多卡部署调优。
- **基础不因优先级降低而跳过。** 张量形状、矩阵运算、Attention、位置表示与损失函数属于算法理解的前置知识，仍按需要讲清楚。KV Cache、MQA / GQA 等先讲机制与应用影响，显存估算提供基础算例，不扩展为部署专项。
- **应用工程仍属主线。** 超时、重试、限流、状态管理、权限、可观测性、灰度与成本控制，因直接影响应用可靠性，仍需结合项目深入学习；不因含有“系统”二字就归入次要 Infra。
- **Agent 是重点能力积累方向。** 后续以第 2.3 节展开路线为核心，深入应用架构、工具与状态、长程任务、数据 / 训练、评测及可靠性；不只介绍模式名称或框架 API。每阶段连接可实现、可验证的练习，复杂多 Agent 不作为起步默认方案。

Infra 教程默认采用“问题与直觉 → 简图 / 核心指标 → 应用层影响与边界 → 官方文档 / 论文索引”的概要结构。只有实际工作需要或主动要求时，才追加底层推导、实现与专项练习。业务场景专题与下方计划均服从这一取舍。

## 2. 2026 核心知识地图

**阅读规则（2026-10-19 去重整理）：只有 [2.3 Agent 主线](#agent-roadmap)中的编号决定当前课程顺序。** 2.1 / 2.2 是前置知识地图，2.4～2.7 是知识归属与按需练习；第 3 节是选题池，第 4 节是当前推进安排，第 5～8 节是复盘、资料和验收工具，不是后面还要再学一遍的课程。

### 2.1 LLM 基础
- Transformer：MHA / MQA / GQA、RoPE、RMSNorm、SwiGLU、KV Cache
- 稀疏模型：[MoE 架构](learning_records/2026-10-09_06_moe_architecture.md)，衔接 SwiGLU，理解 token 路由、总参数 / 激活参数与计算 / 显存边界。
- 微调：Full / LoRA / QLoRA / P-Tuning
- 后训练：SFT → Reward Model → PPO → DPO → GRPO
- 推理参数：temperature / top-p / repetition penalty / structured output
- 评测：MMLU、GSM8K、MT-Bench、LLM-as-Judge 偏差

### 2.2 RAG
- 链路：解析 → chunk → embed → index → recall → rewrite → rerank → compress → generate → cite
- 关键点：chunk size、父子文档、HyDE、multi-query、BM25 + 向量、cross-encoder rerank
- 生产问题：检索错 → 生成错；长文档截断；元数据过滤；引用溯源；abstain
- RAG 专项评测：faithfulness、citation accuracy / recall、召回与排序质量；执行环境和通用统计复用 Agent 第 13、14 课，不另开重复的评测流程课。
- Re-rank 训练（重点专题）：query / candidate 的相关性与支持标签、实际召回与 hard negatives、分组划分 / 防泄露；pointwise、pairwise、listwise 目标的选择与排序 / 端到端评测。与 embedding 对比训练分开讲解。

RAG 教材顺序：总体链路 → 文档解析 / chunking → embedding 与检索基础 → BM25 / 混合检索 → Re-rank 数据与训练目标 → 查询优化与上下文压缩 → 完整评测实验。

### 2.3 Agent（唯一顺序主线）

目标：能解释并实现一个有明确权限、持久状态、失败恢复、独立评测与成本约束的 Agent；能判断何时应该用确定性 workflow，而不是增加模型自主性。

**讲义规则：先总体架构与前置概念 → 具体流程 / 图示 → 数据与实现 → 失败模式 → 评测与实践复盘。** 框架、产品与基准需核对版本和公开证据，不从产品外观推测内部实现。以下是待开展路线，不代表已完成实践。

##### 可选扩展：与 DeepSeek Harness 的设计对照

2026-10-19 新增。**当前仅登记主题与分析提纲，正文待展开**；不增加必修课、不替换实践 01，也不恢复历史“2 个精读 + 1 个对照”的必做安排。

**扩展 1：[OpenClaw](https://github.com/openclaw/openclaw) 与 DeepSeek Harness：设计目标与侧重点的主要区别**

- **服务谁、解决什么问题**：比较目标用户、典型任务和产品边界；区分个人助手的使用体验与可复用 Agent 运行能力，不把两者简单分成“有 / 没有 Agent loop”。
- **一次任务怎样进入并运行**：以同一周报任务追踪消息入口、Gateway / 服务入口、会话路由、Agent 执行与结果返回；哪些对象常驻，哪些随任务创建，定时或外部事件如何触发工作。
- **产品能力怎样影响架构**：对照多渠道、设备接入、跨会话状态、工具 / Skills 与权限边界；分别确认默认能力、可选组件和依赖外部服务的部分。
- **取舍与可借鉴设计**：哪些设计服务于持续个人助手，哪些适合独立任务运行或二次开发；我们的周报项目值得借鉴什么，暂不需要什么，以及相应维护成本。

**扩展 2：[LangChain Deep Agents](https://github.com/langchain-ai/deepagents) 与 DeepSeek Harness：组装方式与运行时职责的主要区别**

- **抽象层次与依赖边界**：从 `create_deep_agent` 的组装入口对照 Cordis 插件 / 服务装配；追清 Deep Agents、LangChain、LangGraph 与 DeepSeek Harness 各层分别负责什么，不把外层 API 当成全部运行时。
- **谁真正控制执行与状态**：比较模型调用、工具分派、暂停 / 恢复、持久化和取消的责任归属；区分框架提供的机制、调用方配置和应用仍需实现的语义。
- **长任务能力怎样接入**：对照规划、文件后端、上下文压缩、Memory、Skills 与子 Agent；关注 middleware / backend 与插件 / 服务如何扩展、组合及覆盖默认行为，而不是只列功能名。
- **开发体验与选型代价**：同一周报任务各需编写哪些胶水代码、配置哪些存储和执行边界；比较定制自由度、默认行为、调试和测试成本，不将 Python / TypeScript 的语言差异当成核心架构结论。

**两篇统一的展开方式：** 先走同一个任务，再提炼主要差异与设计理由，最后给出适用场景和项目借鉴点。每个结论区分官方说明、固定源码证据与分析推断；未验证的能力明确保留为问题，不把功能数量、项目热度或示例运行当成效果排名。版本入口沿用下方历史记录，正式展开时核对引用与版本；本次不新增源码分析、下载或运行。

**开展方式与交付物：**

1. **先项目全貌，再概念映射**：先讲项目定位、部署 / 运行方式、目录与核心术语、生命周期；再走完整 loop，最后选择规划、上下文或记忆机制深入，不从零散文件开始。
2. **统一任务**：先用只读“读文件 → 搜索资料 → 回答与引用”，再在可丢弃仓库做“改一个小函数 → 跑测试 → 根据失败修复”。是否调用模型由预算和用户授权确认。
3. **先模拟再实测**：用记录 / 模拟响应追控制流，随后在隔离工作区测试正常、工具失败、取消、上下文超限、暂停 / 重启等场景；安全测试范围与项目能力匹配。
4. **每项目输出**：架构图、一次完整调用时序、概念 → 模块 / 符号表、关键配置与限制、1～2 个测试证据。展示已验证结果与尚不确定之处。
5. **横向比较**：模型和任务尽量固定，报告工具、预算与环境差异；重点是设计取舍，不以 stars 或某次演示决定优劣。
6. **只选一套做自己的完整项目**：2～3 个仓库用于读架构，不代表维护 3 套项目。手写最小 loop 仍作为理解与测试的基线。

- Attention / 缓存：FlashAttention 的分块与 online softmax、避免显式存储完整注意力矩阵；KV Cache 的基础估算回看[原课](learning_records/2026-10-09_02_kv_cache_mqa_gqa.md)，不把缓存显存当成总显存。

- 并行与通信：TP / PP / DP / EP；MoE 的 all-to-all、load imbalance、capacity factor；NVLink / InfiniBand 的协作边界。
- 数值与工具链：AWQ / GPTQ / FP8 / INT8、TensorRT-LLM / Triton。
- 工作需要时再展开：70B 多卡与目标 QPS 的容量分析、IO-aware / memory-bandwidth-bound、kernel fusion、Nsight 性能排查。不是当前必做部署任务。

外部入口统一放在第 6 节；不再在业务场景和阶段计划中重复展开这份清单。

## 5. 技术分析与设计复盘框架

这是遇到具体问题时使用的模板，不单独排课。技术解释仍沿用开头的“是什么 → 为什么 → 怎么做 → 为什么这么做”；复盘只补充这次事件的证据：

1. **问题与范围**：哪里未达标，影响哪些任务与版本。
2. **事实与证据**：输入、实际 request、工具结果、产物与判分。
3. **归因与备选**：数据、检索、模型、工具还是状态问题；哪些仍是猜测。
4. **改动与取舍**：为何选规则、RAG、Skill、训练或多 Agent，其他方案为什么不选。
5. **对照与结论**：独立任务上的收益、代价、退化、未解决问题及下一步。

详细的评测、trace 与训练选择分别回到第 13～15 课；不在复盘模板中再次展开。
